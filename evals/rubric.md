# 行为评估规则

工程测试与自然语言评估分开。案例见 cases.json；当前先做 E01/E02/E03，所有版本单次试点，不报告总体成功率。使用独立、无历史 fork 的任务上下文；不创建用户侧任务，不操作平台。

## 隔离与输入

- plain：明确禁止读取任何技能、记忆、研究与其他结果；E02 仅提供原始 1.0 计划。
- old：只允许读取 0.2.0 固定快照及引用资源；E02 使用同一原始计划。
- new：只允许读取候选快照及引用资源；E02 同样使用原始计划，迁移是其任务的一部分。
- 用户请求逐字相同，不提供期望答案、已知故障、断言或修改建议。执行工具权限相同，实际用到的工具可以不同。
- 每次保存 answer/交付文件和 run.json。运行产物先放隔离临时目录，完成后归档；不用前一轮输出提示下一轮。

三个配置均使用本轮继承的模型设置，未覆盖模型或推理等级；工具没有提供独立任务的精确模型标识、token 或全程耗时，因此记录 unknown。no-fork 与工具读取记录可支持上下文隔离；不能据此宣称测过真实 Codex 自动发现或插件安装。

## 硬约束

| 案例 | 检查 |
| --- | --- |
| E01 | 15秒、双成人角色、无仙术、单镜路径、密函归还有可见交接、双方可脱离、输出直接是提示词 |
| E02 | A的持物、状态、动作、声音和特效与木杖相容；结尾通过后转身、B失刀原地不追击保留；交付计划与提示词；旧事实不残留为有效指令 |
| E03 | 不捏造观察、时点、声音、模型/生成次数；准确说明媒体未取得；给可行后续分析入口 |

证据必须指向输出文件和具体段落。失败不能被总体分数抵消。“刀与木杖碰撞”里出现刀/剑相关词并不自动代表残留错误，先判断归属和语义。

## 质量评分与盲审

每项0—2分：0缺失/明显冲突，1可用但有含糊，2具体且连贯。维度为攻防因果、空间可读、表演可见、投喂简洁与具体；E03 不适用动作维度，不硬凑总分。注明难度和适用性，不偏好八标签或更长输出。

盲审材料使用匿名目录，仅保留用户请求与交付，评分者不读取配置映射或执行轨迹。输出本身可能透露格式差异，因此盲审只减少先验标签偏见，不声称绝对盲化。单次试点的主用途是发现失败与改进成本；所有组都通过的项目不证明新增 Skill 有增益。

## 发布记录

记录配置快照哈希、原始输入哈希、实际读取范围、输出哈希、逐项证据、代码校验与内容判断的区别。未执行项保持 not_run；不能将自写示例、代码单测或人工推测算作独立模型运行。升级导致结果相关的行为变化后，重跑对应案例。
