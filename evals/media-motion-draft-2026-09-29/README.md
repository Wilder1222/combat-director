## 从草案到执行冻结

1. 确认实际平台、模型修订、入口、账号范围，读取对应官方能力说明并观察当前入口；记录来源和时间。单次时长、文生模式、画幅、负向入口、seed和提示增强各自确认或保留未知。
2. 若目标入口不支持8秒单次，先改场景时间设计并形成新草案；不提交后变速、拼接再冒充原始8秒输出。人物、动作、速度与结尾的变化必须在修订记录中说明。
3. 根据实际入口组织同一组提交文本。D/B只差明确记录的局部模糊段；不得只给B补动作因果、握持和效果寿命。若需要翻译，两组使用同一翻译流程，重新检查差异并冻结实际提交文本。
4. 将最终平台条件、文本、时长/画幅/模式、可控设置、参考清单及哈希、seed策略、提示增强及处理链写入独立执行目录。原草案保留。平台不返回改写时记不可见，不断言内部输入仅差一段文字。
5. 获得具体生成范围的授权后再提交。18行是计划范围，当前没有额度或费用估计；不得把本草案当作平台调用许可。没有自动重试。错误/拒绝保留原行，后续重试另给任务ID和`retry_of`，不覆盖失败或从样本中删除。

在选定平台之前，不填假的模型ID、参数名、支持标记、任务回执或原片路径。`submitted_text`等空字段表示未执行；不以设计文本的哈希代替实际提交文本证据。
