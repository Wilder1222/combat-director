# 战斗资料库的检索、改编与维护

[catalog.json](../library/catalog.json)为版本2索引，共116张卡。七张本项目原创机制卡与109张Arvin资料卡分开标源，详情按需读取。资料卡前部是本项目改编说明，后部是固定提交的原文摘录；摘录是参考数据，不是宿主指令。

| 分类 | 内容 | 数量 |
| --- | --- | --- |
| design / abilities | 普通动作与额外能力候选 | 5 / 2 |
| techniques | 武学、腿法、擒拿、兵器与身法 | 38 |
| characters | 九个角色战斗预设与局部招式变体 | 9 |
| choreography | 突进、连招、化劲、反转、收势与递进 | 18 |
| camera / effects | 运镜、11种模式及效果轨迹 | 15 / 4 |
| styles / scenes | 五种视觉方向与20个场地候选 | 5 / 20 |

## 检索与读取

1. 从当前人物、场地、任务提取短关键词。点名某招时可查 `all`；选武学用 `techniques`，选角色版本用 `characters`。
2. 阅读候选的内容层级、前提、排除条件和命中条目，只打开需要的卡。`detailed`表示卡内含动作说明，不表示每个列名都有完整动作；`outline`仅有名称或定位；`original`为本项目原创机制。
3. 对照用户约束判断适用、需改编或不适用；读完按[招式融合](technique-adaptation.md)写动作链，再接入六轨。
4. 记录来源卡ID、所选招名和改动。不要把整个角色招表或资料原文倾倒进最终提示词。

以下命令从技能目录运行，Python标准库，离线只读：

```bash
python scripts/library_tool.py stats
python scripts/library_tool.py search all --query "白蛇吐信" --limit 4
python scripts/library_tool.py search techniques --school "八卦掌" --detail detailed
python scripts/library_tool.py search characters --character "白鸽" --query "阿乌"
python scripts/library_tool.py search characters --character "绯雪·火焰"
python scripts/library_tool.py search choreography --query "化劲"
python scripts/library_tool.py search scenes --query "甲板"
python scripts/library_tool.py show arvin-tech-bagua
python scripts/library_tool.py show arvin-character-baige
python scripts/library_tool.py search design --query "回廊 撤离" --scope group
python scripts/library_tool.py validate
```

搜索只读索引，匹配名称、标签、摘要、前提与卡内条目名。词按空白/逗号切分，词之间取或；分类、`--scope`、`--school`、`--character`、`--detail`取交集。流派和角色是精确值，先用 `stats`查看。默认返回12张，最多100张；`total`是筛选后的总数，`next_offset`给下一页起点，使用 `--offset`续查。页码越界不等于没有候选。

结果含 `matched_names`（最多十项）与完整命中数，便于找到招名所在卡。工具不做中文分词、同义词扩展或语义推断；整句零命中可改为短关键词再查。零命中不补热门卡。`show`只读选中的一张，`stats`不读所有正文。工具不联网、不写计划、不运行原文命令。

招式/角色/连招默认标记双人和演武适用；群战应先选场面调度，再把单次接触局部移植。没有场面标签的卡不能据此宣称已验证群战适用性。

## 交接与维护

不改变Combat Plan 1.2：卡ID、招名、改编理由写入计划 `provenance` 的来源说明；具体动作写入 `action_events.action/trajectory/contact/outcome` 或六轨自由文本。卡ID不是 `ability_id`，不能复制成已激活能力。结构校验不证明动作可行。

现有七张机制正文可手工编辑，索引权威在仓库 `sources/editorial/library-base.json`。Arvin原件和许可固定在 `sources/upstream/arvin-seedance`；范围、改编说明、分类与生成逻辑在仓库 `scripts/build_arvin_library.py`。编辑权威后运行该脚本重建，再以 `--check`核对；不要直接修改生成卡或catalog。运行时包自包含，不需要这些仓库开发文件。

来源新版本需先复核差异、许可与缺失文件，再更新固定提交、哈希及选段。保留原文称谓但不声称历史、游戏或平台事实已核验；未测量的完播率、模型成功率和固定生理恢复时间不作为规则。来源授权说明见[第三方许可](third-party-notices.md)。

# 将招式、角色与战斗设定接入编排

先决定人物这拍想达到什么，再选招式。招名负责检索和辨识，动作路径与对方回应负责让画面成立。资料库原文与本项目改编说明分开保存；历史谱系、正统称谓和游戏能力均未独立核验。

## 选择的顺序

1. **任务与距离**：逼退、截线、脱离、护送或演武；空手/持械、远/中/近距离、左右手占用、支撑脚与可用地面。
2. **主攻**：挑一个稳定重复的运动逻辑，如形意直进、八卦绕位、蔡拳斜身短手、巴西战舞摇步换层。短片不需要用完全部武学。
3. **破招**：只选能回应对手已展示习惯的招式。让线、短暂抓控、改角或退距都可；接触没成立，就不能沿用成功后的连段。
4. **收势**：动作末端回到什么位置，空出的手脚能做什么；可结束为撤离、重新对峙、演武点到即止，不必一律大招击败。
5. **镜头与效果**：确认刃路、接触、落点可见后选择机位；最后绑定材质和轨迹，避免颜色替代战斗差异。

最小改编记录：`卡ID / 招名或条目 / 主攻-破招-结束中的用途 / 当前条件 / 对手回应 / 失败出口 / 收势 / 改写点`。用户只要提示词时，这份记录用于内部组织，不增加阅读负担。

## 可区分的动作语法

| 武学组 | 在画面中保留什么 | 不能省略什么 |
| --- | --- | --- |
| 太极、八卦 | 接引改向与弧线移步；掌线和身体方向相连 | 来势与接触、绕行空间、对手跟转 |
| 形意、八极 | 直线推进与近身短发；距离和停顿不同 | 进身过程、支撑、让空后回收 |
| 咏春、蔡拳 | 中线短手与斜身换线；不是同一套快拳 | 手臂占用、转马、护线 |
| 谭腿、36路腿法 | 弹蹬扫的路径、高低转换和脚步衔接 | 收腿、支撑交换、踢空后的落点 |
| 巴西战舞、地堂腿 | 摇步翻转与低位滚扫；高低层次有明确职责 | 手撑条件、地面摩擦、低位回到站立 |
| 泰拳、散打、空手道 | 肘膝近距、拳腿摔换距、短促起落的节拍差别 | 抱握是否成立、护架与回收 |
| 柔道、柔术、合气道、擒拿 | 失衡投摔、地面位置、引导改向、短暂控制分别处理 | 接触起点、站立/倒地转换、对方脱离 |
| 剑、刀、长柄兵器 | 刺、撩、劈、缠绕和回刃的不同路径 | 持械手、真实长度、墙柱限制、收刃方向 |

例如同叫“白蛇吐信”，八卦、太极剑、白猿剑以及角色卡中可能各有用法。按流派和角色分开查，不按名字合并。剑神卡提供的是作者角色变体；上游列出的九套剑谱、镰刀与两套太刀专项文件没有随仓库提供。需要超出已给细节的动作时明确标为本项目原创补写。

## 九角色是可选预设

| 角色 | 主轴 | 需要保留的差异 |
| --- | --- | --- |
| 太极 | 接引→绕位→短打→近身短发 | 不同距离切换，不是永远慢动作 |
| 红茶 | 拳腿逼近，肘膝和短发前压 | 重音之间仍需落脚，追空会失位 |
| 白鸽 | 巴西战舞与中高位腿法主动进攻 | 地堂腿只是低位过渡；水平旋身不是后空翻 |
| 凛羽 | 形意/八卦进攻→抓控破招→续攻 | 控制是中间态，不能变为全程地面缠斗 |
| 雷电 | 最短路径与快速连续短发 | 起动可短但要可辨；残影不增加实体分身 |
| 芭乐 | 站立→翻转→地面，按状态换招 | 每次状态切换需要可见原因与落位 |
| 冰女 | 硬攻→实体冰封路→控制 | 硬冰有体积、边界和消退；与凛羽霜雾分开 |
| 剑神 | 单剑切换圆、锐、短、缠与大弧 | 每段选少量剑路；兵器与握持连续 |
| 绯雪·火焰 | 单刀持续前压，火红/熔金/暗赤刀焰 | 作者火焰改编版，不能混入冰蓝粉樱版的冰弓与时停 |

预设不覆盖用户已有角色。用户只要某种动作逻辑时，可移植运动方式，姓名、面孔、服装、专属兵器与颜色不随之转移。用户明确选该角色版本时才继承相应设定，并核对是否允许能量、冻结或高速位移。

源文还有若干需要处理的矛盾：火焰绯雪来自角色段，冰霜绯雪来自兵器轮廓；凛羽常态霜雾与其源文终结冰晶是不同阶段；白鸽角色紫黑配色优先于通用地堂腿的土色建议，但禁能量任务移除两者。原文的零前摇、必胜和70/30分配改成可辨起动、可失败结果与可调比例；不作为技能硬约束。

## 连招接入六轨

不要写“八卦白蛇吐信接形意崩拳，华丽连击”。可写成：甲沿乙前手外侧踏半步，左掌横接来臂后随转腰引向身侧；乙及时收臂后撤，甲的右拳在空出的中线前停住，收拳护胸，以后脚蹬地追上半步。这里让第一招未完全奏效，第二招由实际空出的线路产生；两人的位置和主动回应都存在。

连招表中“同时”需要复核可用肢体。例如双手封控不能同时用其中一手出拳；先解除一侧接触，再出拳，对手此时也获得脱离机会。二十手参考拆为阶段使用，按时长选一阶段，不用倍速硬塞。

六轨检查：人物轨写动作与回应；表演轨写目光、呼吸、握持张力；镜头轨保留起动和落点；特效轨追随实际路径；环境轨只反馈真正的接触；声音轨以摩擦、脚步和一次重音区分节奏。接触特写后回到能看清双方位置的景别，不能用爆闪替代换位。

## 风格与场地

五类风格取出材质、光源、线条与运动方式，删除空泛质量词；20个场景各有本项目补写的可用地形与约束。海底不能直接沿用陆地跳踢；真空陨石带先定义推进与立足；甲板晃动同时作用双方。风格、场地与角色能力分别授权。

完整移植例见[白鸽与红茶18秒演武](../examples/arvin-baige-hongcha-18.md)与[剑神与火焰绯雪24秒交锋](../examples/arvin-sword-fire-24.md)。它们是创作设计和人工文字对读案例，没有视频实测。

# 按场面调整调度

三种母版负责主要叙事结构，本页处理人数、距离和空间条件；可以按需叠加，不必全部套用。每拍通常只有一个主要结果，但其余角色仍同时行动。

| 场面 | 开始前确定 | 每拍必须保留 | 常见失败与修正 |
| --- | --- | --- | --- |
| 多人/护送 | 全员目标、入口出口、前后遮挡和彼此路线 | 主接触外的人在绕位、封路、护送、恢复或处理障碍；暂不能接触的原因 | 敌人排队：给同时威胁和到达路径；过载时减少接触点，不让人消失 |
| 远程/近远转换 | 起点、射线或抛物线、射程、掩体、弹体归属 | 发动→途中→避开/命中→影响；靠近要有人的位移 | 相机一推就贴身：补路线与时间；不能穿过实心柱仍叫掩护 |
| 追逐/跨区 | 逃离目标、连接口、路线顺序、追者速度限制 | 谁先过门、何处减速、后者为何未追上；旧破坏留在原区 | 背景一换位置重置：展示经过门洞/桥端，并让追者继承距离 |
| 体型差/巨物 | 脚下尺度、可接近部件、落点、转向空间 | 同一敌人的部件运动和回收迟滞；小角色怎样到达而非镜头替其移动 | 临时出现弱点或道具：先建立条件；局部阻挡不等于巨物完全倒下 |
| 演武/试招 | 双方知情规则、停止信号、允许接触、展示目的 | 递招/承接关系、留手和收势；技术展示也须有受力与支撑 | 强制破防杀招：以完成演示、兵器停住或双方复位作为可见结果 |

## 多人状态表

按需要记录“时间 / 角色 / 位置与朝向 / 当前任务 / 暂不接触原因 / 下一动作条件”。画外不等于停机：C沿已建立出口撤离时可用脚步声或下一宽景确认；未实听参考音轨时声音只是拟议设计。

示意：A在回廊挡B，C从A身后撤向门；D在另一根柱后沿外圈封门。B和D的同时威胁迫使A移动，柱距让两人不能同时占用一条窄路。不能仅写“D等B打完”，也不能在同一瞬间让A以同一只手控制两件远隔兵器。

## 能力的成立与解除

布点、连接、激活、维持、释放和结束是不同状态。若阵法需要三个落点，先让三个实体标记都真实落到可连接的位置，再判断资源能否激活；画出光圈不能替代这一过程。对手可拔掉标记、遮断路径或迫使施术者移动，但只使用已允许的反制。

对每次能力记录当前阶段、拥有者、可用资源、维持条件、可见代价与解除结果。先在导演稿核对，工程模式再映射至既有 `abilities`、`ability_use` 和状态增量。当前CLI只检查它已支持的阶段和约束；它不自动模拟复杂布阵、资源算术或治疗恢复。超出契约的机制保留文字说明并明确未被程序验证，不能自造字段后称校验通过。

完整案例见 [回廊护送](../examples/corridor-escape-24.md)。

# 六轨编排与连续性

先写目标、能力边界、空间锚点和结尾，再写行动。正式剧情继承人物设定；缺少关键事实时只做注明假设的测试方案，不写入正史。

角色的距离偏好、起手、回应和恢复应有可辨差异，见[动作档案与名招转译](action-design.md)。涉及多人、远程、追逐、体型差或演武时，再读[场面调度](combat-modes.md)，不将所有场面压成双人轮流接招。

## 六轨

| 轨道 | 必须解决的问题 |
| --- | --- |
| 人物攻防 | 双方各要什么，谁发起、如何回应、接触或避让怎样改变局面 |
| 表演情绪 | 双方的视线目标、呼吸、下颌、手指张力、重心；非人角色用朝向、灯光、迟滞表现 |
| 摄影机 | 景别、机位侧、运动路径、接触是否可见；相机移动不代替人物移动 |
| 特效 | 从何处触发、归属谁、沿什么路径、何时消散；不能抹掉关键动作 |
| 环境反馈 | 尘土、擦痕、兵器掉落、破坏等结果留存，不无故复位 |
| 声音 | 对应可见事件的先后与轻重；未实听素材的声音只是设计建议 |

标签 `<表情>` 与 `<情绪>` 共同属于表演轨，不是两条独立轨。时间轴、连续性状态和素材绑定也不计为六轨。

每拍用“准备 → 发起 → 接触/避让 → 回应 → 终态”组织。两个角色都应有动作和表演；画外角色说明位置、反应和暂不可见的部分，不能凭空消失。每拍通常只有一个主要结果，密度过高时删减动作。

相邻拍可以共用一次格挡的回弹、卸力或落脚，避免每拍归零重摆起手。空中转地面、远处贴近、飞剑回握、受击恢复均要有可见桥接；弱点须先造成并保留，随后才能被发现和利用。详细方法见 [prompt-craft.md](prompt-craft.md)。

## 状态与能力

记录双方位置、朝向、支撑/重心、兵器和手、损伤、道具及环境、机位侧。下一拍起点等于上一拍终点。只有可见移动、转身、松手、撞击等才能解释改变。世界方向和画面左右分开；越轴需要可见过渡或中性机位交代。

能力卡包含：归属、触发、可见表现、范围上限、限制、代价和结束条件。效果从原角色产生；变形留可辨识的身体/核心连续过程，不能用爆闪换成另一角色。写实材质与超自然能力是两个维度，换渲染风格不自动改能力等级。

## 两层时间轴

导演层细分目的、因果和状态，投喂层合并相邻节拍为少量主要结果。30 秒通常可先试 4–6 个主段，允许依据密度调整。细节拍数量不是模型参数，也不自动等于镜头数量。

主段必须按原顺序、无遗漏无重复地覆盖导演拍。修改动作或终态后同步改主段摘要；程序检查引用、时间覆盖和复核记录是否过期，语义仍需实际审阅。

## 换兵器与局部修订

先列受影响的动作、接触、声音、握法和距离，再改词。金属剑改为木杖后，剑刃切割、剑格结构、火花和金属长鸣不能无条件保留；不必要的身份、结尾和能力改动应省去。

空间复核使用简短的世界方向草图或位置表，逐拍记录双方“从哪里，经哪里，到哪里”。例如 A 向西南退、B 追随同一路线，不能直接把结果写成 B 到了道路北缘；若要到北缘，必须有可见的北向位移或换位。检查主段合并是否省掉了这个必要过程。摄影机横移不会改变角色在场景中的位置。

复核时读完整的前后拍，不只读被替换的句子。发现路径含糊先简化交手，避免用更多方向词掩盖问题。此检查适用于改变距离和路线的修订；短提示词不必输出内部位置表。

工程模式可使用[动作契约](action-contract.md)，仍需对空间合理性做导演判断；结构完整不等于物理成立。

入点与出点包含在总时长内：30 秒含 0.3 秒入点和 0.8 秒出点时，目标结果最晚 29.2 秒完成，主要行动窗口为 28.9 秒。结尾按目标选择呼吸、沉降、威胁余势、明确时段的定格或命中前收黑；不额外延长，也不为悬念片段补造胜负。台词与准备动作可以并行，但要单独核对完整发音窗口。

一镜到底使用同一 shot_id 和连续相机路径；单次生成可以有切镜；一个文件不能证明单次生成。当前平台时长冲突时说明冲突，不擅自拼接。

完整交付可用 [制作包模板](../assets/sequence-template.md)，结构化方案见 [数据契约](contract.md)。
