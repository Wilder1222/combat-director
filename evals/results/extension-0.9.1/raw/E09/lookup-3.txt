# Combat Plan 1.2：事实、表达与复核

权威结构：[当前 Schema](../assets/combat-plan.schema.json)。[1.0 Schema](../assets/combat-plan-v1.schema.json) 只供迁移与结构检查。软件版本和数据契约版本分别维护；文本创作不强制填写 JSON。

当前兼容读取 1.1，1.2 增加可选动作结构与素材证据。旧案例不被强制补写未知动作事实；1.0 必须显式迁移并重新复核。已标 available/bound 的旧素材声明需补证据，不能仅迁移版本号后当作已验证。

## 字段职责与交接

| 字段 | 权威角色 | 交付位置 |
| --- | --- | --- |
| duration / aspect_ratio / generation / camera_mode / timing / rules | 时间、镜头和能力的硬约束 | prompt 硬约束、设计卡、交接单 |
| cast / abilities / anchors / initial_state | 人物、持物、能力和开场事实 | prompt 硬约束、导演稿、编译交接 |
| beats | 动作、表演、机位、声音与状态事实 | director.md、prompt-handoff.json |
| weapon_profiles / action_initial_state / action_events / state_delta | 可选具体交手；启用时为动作状态的唯一权威 | prompt 具体交手、投影状态、编译交接；见[动作契约](action-contract.md) |
| sections.beat_ids | 投喂段选取的连续细拍 | 导出时间范围与交接记录 |
| headers / sections.summary | 人工或 Agent 编写的表达 | prompt.txt；需要语义复核 |
| editorial_reviews | 对特定输入和表达版本的复核声明 | 计划与状态检查；不是视频验收 |
| id / provenance | 文件身份与来源说明 | 计划和设计卡；不参与语义摘要哈希 |

每拍记录全部角色的动作与表演。before 继承上一拍 after，包括角色、environment、camera_side。第一拍 transition=start；之后 continuous 保持 shot_id，cut 改变 shot_id。一镜到底全程一个 shot_id，越轴需要可见过渡。状态文字相等不证明物理成立。

## 修订流程

改动事实或表达后，先检查状态，再编译供复核的内容：

```bash
python scripts/combat_tool.py status my.plan.json
python scripts/combat_tool.py compile my.plan.json --out review-input.json
```

review-input.json 按 headers 和各主段提供 facts、expression、input_digest、expression_digest。独立比较两者，修正遗漏或矛盾，再编译。重点是身份/动作、镜头/时间、能力/代价、连续性；不能只看标签齐全。

将实际复核结论保存为 receipt JSON。每条必须复制所检查版本的两个 digest，并用具体证据填写四项 checks：

```json
{
  "plan_id": "your-plan-id",
  "reviews": [{
    "scope": "P01",
    "input_digest": "从review-input中复制的64位哈希",
    "expression_digest": "从review-input中复制的64位哈希",
    "reviewer": "实际复核者名称",
    "method": "agent",
    "checks": {
      "identity_action": "说明该段兵器、动作和回应与细拍如何一致",
      "camera_timing": "说明该段时间与镜头规则如何对应",
      "ability_cost": "说明能力限制/代价的表达；无能力时说明不适用",
      "continuity": "说明起止状态与相邻段的关系"
    }
  }]
}
```

示意哈希不可直接执行。method 可选 human 或 agent。receipt 可只包含重新检查的 scope；其余旧记录保持，但不能绕过已失效的检查。

```bash
python scripts/combat_tool.py apply-review my.plan.json --receipt receipt.json --out reviewed.plan.json
python scripts/combat_tool.py validate reviewed.plan.json
python scripts/combat_tool.py render reviewed.plan.json --platform generic --out-dir output/check
```

ready 仅表示复核声明对应当前事实和表达。stale 表示内容已变化；needs_semantic_review 表示没有复核声明。后两者阻止正式导出。不要为通过导出而只刷新哈希：程序无法判断复核者是否认真读过内容。

全局人物/能力/时间变更影响所有段；某段动作或摘要变化影响本段；前序结束状态和能力变化也影响后续段；最终状态变化会使总设定复核失效。哈希对 JSON 对象键顺序、数字 1/1.0、文本首尾空白和行尾差异归一化，保留正文内部语义差异。

## 旧计划与文件保护

```bash
python scripts/combat_tool.py migrate old-1.0.plan.json --out migrated.plan.json
```

迁移保留事实和表达，新增空的复核记录；不自动确认旧摘要正确。compile、migrate、apply-review 默认拒绝已有输出、链接路径及源文件覆盖。render 导出 7 份：design-card.md、director.md、prompt.txt、prompt-handoff.json、handoff.md、review.md、combat-plan.json。只有 render 提供显式 --force。

validate 和 render 接受 --max-duration 15；确认平台上限为15秒时，30秒单次计划失败，不自动拆分。内置平台模式保持未知；可使用带证据的 --profile 文件进行能力冲突检查，见[平台交接](platforms.md)。审片记录与下一段起点见[审片回流](review-loop.md)。

校验器审计随包 Schema 的关键字；未知断言明确失败，不静默忽略。它是标准库实现的有限子集，并额外拒绝要求非空的纯空白字符串，不是通用 JSON Schema 引擎。结构、引用与复核版本可由代码检查，表达忠实性仍由复核者负责。

# 审片记录与后续起点

用户给出视频、抽帧或观察报告后，先确定证据来源和观察范围，再记录完成事件、缺失事件、额外事件与结束状态。未看到的事实写 unknown；不要拿计划结束状态填补观测空缺。

## 创建与检查记录

```bash
python scripts/combat_tool.py review-template my.plan.json --take-id take-001 --out take-001.review.json
python scripts/combat_tool.py review-take take-001.review.json --plan my.plan.json
```

模板默认 unobserved / pending，所有观测状态未知。[审片 Schema](../assets/take-review.schema.json) 固定源计划摘要，防止把另一版计划的结果混进来。

media 记录素材 ID、位置、可取得的哈希、证据类别、观察方法、时间覆盖和是否实听音轨。actual_media 表示记录作者声称实际查看媒体，user_report 表示用户转述，synthetic 是合成教学夹具。脚本不读视频内容，结构合法不等于该声明已经被独立核实。真实媒体工作应保留宿主读取、抽帧或播放记录。

full_video 的覆盖必须连续包含总时长；frames 只支持所列时间点/范围，不证明中间动作连续。未实听不能写 audio_observed=true；脚本拒绝用抽帧、用户转述或合成夹具声明音轨已听。用户报告可以支持创作修订，但始终保留来源标签。

completed_events / incomplete_events 引用已声明拍或事件；不能同时标完成与未完成。unexpected_events 写计划外观察。deviations 包含时间、观察、影响、修复；不得把修复设想写成已经生成的事实。

运动成像审片另记正常播放和局部连续帧各自覆盖的范围；原片、插帧、补模糊和变速版本分别记录素材位置与哈希。用现有 deviations 描述接触遮挡、持物粘连和风格偏差，不新增未经支持的字段。看不清关键事件时保留未知或未完成，不能以文件FPS、锐度或计划意图补全观察。诊断顺序见[运动成像](motion-blur.md)。

需要比较生成条件时，将审片记录关联到制作包中的实际提交文本、模型/入口/模式、提示增强状态及返回改写或不可见状态。它们属于执行依据，不证明画面已按文本实现。原片与后期版分别观察；后期修好不能倒写成原模型已满足。执行信息保存在[平台交接](platforms.md)所述记录中，审片 Schema 沿用现有字段。

## 接受与修复

| decision | 后续用途 |
| --- | --- |
| pending | 尚未处理，不作连续性起点 |
| accept | 无已记录偏差或未完成项；附决策者、理由和状态证据 |
| accept_with_deviation | 明确接受哪些偏差及其影响，后续以观察结果为起点 |
| repair | 保留失败证据，只修改相关事件/主段后复测 |
| reject | 不进入后续状态链 |

接受决定沿用用户已给出的选择；不要凭校验通过就擅自把失败 take 设为接受。用户明确要求自主选片时可在其标准内判断，并记录理由。

```bash
python scripts/combat_tool.py continuation-seed take-001.review.json --plan my.plan.json --out next-start.json
python scripts/combat_tool.py check-continuation take-001.review.json --plan my.plan.json --next-plan next.plan.json
```

种子只携带已接受的 observed_end_state、来源和未解事项，不自动重写旧计划或生成下一场。next.plan.json 的 initial_state 必须与该观察状态相同；若含 unknown，需要继续观察或在新创作中显式说明假设，不能偷换成计划原状态。启用结构化动作时还必须为该观察状态建立一致的结构投影。

明确单次生成/一镜到底的任务，优先修订同一个任务；这里的种子机制不授权自动拼接。最小修复报告格式继续使用[质量检查](quality.md)。

# 审片与最小修复

区分文本预检、结构校验、实际视频验收。只有读取过的画面和实听音轨能形成媒体证据。未生成视频时给待填验收项，不声称已验证观感或成功率。

| 优先检查 | 证据 | 最小修复 |
| --- | --- | --- |
| 身份与持物 | 换脸、换手、兵器复制、终端消失 | 固定绑定、持物手和可见交接 |
| 空间与支撑 | 瞬移、越轴、漂浮、穿过场景 | 补路径、重心、机位过渡 |
| 攻防因果 | 对手不回应、未接触先飞出 | 拆开准备、接触、反应和恢复 |
| 双方表演 | 眼神失焦、无呼吸、敌方无状态 | 写清双方视线目标、张力和节奏 |
| 能力与代价 | 无条件开大、变形换人、无限复制 | 恢复触发、限制、结束与资源消耗 |
| 环境继承 | 落刀消失、印记重置、货架复位 | 继承上一拍状态 |
| 可读性 | 特效遮脸遮动作、镜头过密 | 减特效、放宽景别、合并主段 |
| 节奏与声音 | 动作塞满、结尾截断、音画错位 | 降低负载、保留余量、匹配事件 |

报告：时间码或文本位置 → 证据 → 影响 → 修订 → 保持不变项 → 复测条件。优先改造成失败的最小部分，保留可比较的输入。结构检查不能做物理模拟，也不能证明主段摘要与细拍语义一致。

代码检查运行 [combat_tool.py](../scripts/combat_tool.py)；输出格式见 [契约](contract.md)。

## 修复示例：装置反制没有成立

[反制失败后修订](../examples/failed-counter-repair-18.plan.json) 是合成教学情境：货架导轨卡住，不能下一拍偷偷落地。修订使用已交代的隔离闸；屏障代价导致右手松杖，后续按钮改由左手操作。保留身份、机甲追踪、场景装置和有限撤离结尾。

复测三点：货架一直卡住；右手失握后不再握杖或按按钮；左手触钮在前、门体下降在后。没有真实视频记录，不能报告重拍成功。

局部修复先锁定事件与状态依赖。若终态改变，后续主段和总设定结尾也可能需要复核；“只修一段”不能忽略真实下游影响。

## 文字方案的专项预检

| 对读位置 | 常见问题 | 最小修订方向 |
| --- | --- | --- |
| 镜头总则 / 局部运镜 | 一镜到底却“切成无人机远景” | 改为有空间路径和时间的后撤升高，或由用户选择切镜模式 |
| 速度总则 / 重点段落 | 全片禁冻结却多处凝滞和终帧定格 | 写明保留的例外与起止；真正冻结时停止相机和粒子 |
| 武器前后状态 | 御剑在外却突然手持斩击；双手施法时原刀无处可去 | 补回程、回握与腾手，删减重复攻击给桥接留时 |
| 早期接触 / 后期反制 | 后来声称“旧裂口”但从未造成，或左右/肩袖位置不符 | 早段补同一处成因，或将后段改为首次形成弱点 |
| 正向能力 / 负向限制 | 禁止复制又无限生剑；绝对禁光球却写独立光球攻击 | 区分实体与投影、局部聚光与独立弹体，明确预算或删冲突能力 |
| 镜头 / 可见范围 | 每帧双方全身清楚却安排单人嘴部特写 | 保留严格可见性时改双人景别；允许暂出画时声明范围 |
| 片段目的 / 结尾 | 首斩前收黑却出现命中声、受伤或胜者姿势 | 截止于接触前，把未知结果留在画外时间之后 |
| 名招 / 身体路径 | 只有功法名就自动挡住攻击，或传统技法自动放出巨型法相 | 拆出可见动作，另核对幻想能力授权、资源与结束 |
| 破防 / 下一回应 | 兵器被压到身侧后立刻完整格挡 | 先避让、落脚、回收；没有恢复条件就继续承压 |
| 多人 / 空间任务 | 主角交手时其余人停住、画外瞬移、没有原因不能出手 | 逐人补路线、任务和受阻原因，减少同时接触点 |
| 机制候选 / 计划能力 | 搜索命中就默认拥有法器、预算或已激活能力 | 对读前提与现有设定；不适用就舍弃或明确改编 |
| 强度 / 摄影机 | 高燃自动变成定格、密集切镜和每拳气爆 | 分别选择密度、速度、镜头与特效，让接触与结果可读 |
| 粒子 / 触发与参照 | 挥空爆出命中火花，旧尾迹粘着兵器反转 | 绑定实际接触事件，分开新尾迹与旧尾迹的路径 |
| 粒子 / 材质与结束 | 木杖打出金属火星，停发时擦痕也复原 | 继承材质；区分停止新增、存量消散和环境留存 |
| 模糊 / 相对运动 | 固定背景因挥剑而全幅横拖，跟拍后所有肢体都像素锁定 | 分开相机、主体、兵器与背景的画面运动 |
| 可辨 / 时间风格 | 为看清接触偷偷慢放、定格或临时关闭一帧模糊 | 在原速度与镜头约束内调整构图和叠加效果；保留明确艺术选择 |
| 成像 / 粒子结束 | 自然拖糊像粒子一样在空中漂散，或把残影计为实体分身 | 分开曝光、效果寿命和艺术画法，保持实体与能力边界 |

这些是人工/模型文本复核项，当前 CLI 不自动判定它们。负向词不能按字面机械匹配，例如空气压力壳不必等于发光能量球。保留用户明确的形式选择和局部例外；细则见 [prompt-craft.md](prompt-craft.md)。

特效故障的具体对读方法见[粒子行为](particle-vfx.md)。没有实际视频时，粒子数量、碰撞、时间精度与观感均不能由结构检查代为验收。

模糊与非预期重影按[运动成像](motion-blur.md)定位，分别观察正常播放时的攻防可辨性、前后帧持物连续性和用户风格。全片静止不能靠高锐度通过；单帧截图不能证明接触过程。先检查原图、原片和后期处理链，不凭外观断言TSR或插帧算法。
