# 通用视频生成写法与按能力适配

用于指定模型投喂、图生/参考生成、修改已有视频或诊断模型未兑现的结果。先保留用户的战斗目标与制作方式，再按实际输入和入口能力调整表达；不设默认厂商。普通创作使用下面的共通方法即可，无需选平台、联网或填写能力表。

## 通用正文先成立

跨模型保留同一组事实：人物与兵器归属、起态、必选动作、回应、接触或让空、结果和下一状态。相机、音效与粒子用于呈现这些事件，不替代事件。中文标签、公共设定和按需时长仍遵循生成模板；不因换模型自动翻译英文、删招、降速、改结局或改成分段。

**描述精度跟随输入和目标：** 文生补齐视觉起点；首帧图生集中写变化，同时保留区分双方与接点所必需的信息；已提供的精准动作参考可只写映射、采用范围和差异；没有动作参考、改变兵器或要求指定招式时写清动作链。既不把长稿视为更好，也不把所有打斗压成“激烈交锋”。

多人的称呼以足够辨认为准：单人可简写“人物”，双人相似服装、交叉换位或多人场面用稳定称呼与实际素材绑定，不把官方单人示例的“他/她”机械推广到所有战斗。

## 按输入与任务选择写法

| 实际任务或素材 | 先检查 | 正文承担的工作 |
| --- | --- | --- |
| 文字生成 | 场地、人物、持物与开场是否明确 | 交代可见起态，然后按事件写动作、相机及结果 |
| 图片作为首帧 | 画面是否已接触、离地、变形或带运动模糊；身份/武器是否清楚 | 从已有姿态续写；不让输入图的来势与正文相反；不重复全部静态描述 |
| 身份/场景参考 | 素材实际用途、上传顺序、哪些图片属于同一人 | 映射素材与角色；身份参考不等于锁定第一帧构图或动作 |
| 动作/摄影/效果参考 | 是否实际提供且可读；采用哪个范围和层面 | 说明保留关系与修改差异；换兵器、体型或地形后重新检查可达性 |
| 故事板/关键帧 | 粗略叙事参考还是接口规定的帧约束 | 补足图中缺少的运动与过渡；两张姿态正确不证明中间路径可行 |
| 编辑已有片段 | 被编辑视频、区域/时间及保留项 | 写原状态到目标状态；不把局部效果修改变成重新编战斗 |
| 延长或独立续段 | 原生延长、末帧再图生还是后期拼接 | 继承实际衔接状态；向前延长接回原片开头，向后延长继承原片结尾；不同制作方式不互相冒充 |

## 只在落到具体入口时核对能力

以下是Agent内部判断，不增加用户必填表。沿用已有模型、版本和入口信息；只有真实提交所需条件不明或与硬要求冲突时才澄清。单纯写通用稿不要求用户选择模型。

- **输入绑定**：首帧/尾帧、身份元素、普通参考、动作视频的角色由实际入口决定，文字提到素材不等于已上传或绑定。
- **时间与分镜**：自然语言顺序、粗时码、逐镜时长控件分别处理；多镜开关或分镜字段与正文一致。一镜到底不启用自动切镜方案；写“全程一镜”也不证明控件已正确设置。
- **声音与约束**：核对是否生成音轨、是否可分别控制音乐/对白/动作声，以及负向指令放正文还是专用字段。无声入口的声音要求作为后期意图，不能宣称生成了声音。
- **参数与制作**：总长、画幅、分辨率及输出方式是用户需求；有专用设置时同步设置，正文中的“4K”“更长”不替代真实参数。不在通用模板写死某厂商上限。

能力未知时，先交付自含的通用编排，保持用户约束并注明影响实际生成的未核实项；不杜撰专属语法、素材ID、调用参数或切换模型。指定入口不能满足用户硬要求时说明具体冲突，不暗中改变制作方式。

## 处理官方建议的分歧

| 分歧 | 采用的决策 |
| --- | --- |
| 简短提示 vs 详细导演稿 | 先判断素材已承载的信息；删重复外观和装饰，保留必选交锋及状态变化。简化不是删掉对手回应 |
| 每镜一个动作 vs 连续多招 | 每镜保持明确的主要变化，可包含相连的攻防链；不设“一镜只能挥一次”或固定动作配额 |
| 单镜建议 vs 多镜生成 | 编排镜数按内容决定；生成入口是否支持多镜另核对。一个输出文件或一次请求不等于一镜到底 |
| 正向表达 vs 负向字段 | 通用稿优先描述目标状态，如“剑始终握在右手”；用户禁止项仍保留。选定入口后才转换为该入口支持的排除写法，不套通用负面词套餐 |
| 固定镜头/运镜控件 vs 文字摄影 | 主体运动、环境运动与相机运动分别写；一条连续相机路线可分相位变化，但不同时要求固定和环绕。控件与正文冲突先统一 |
| 短片更稳 vs 用户指定长镜 | 减少同时精确兑现的可选变化；仅在允许时拆段。保留用户的速度、时长和单次生成要求 |
| 参考一致性 vs 必须逐镜重复角色 | 公共模块集中稳定设定；独立请求带齐自身身份和状态。同一请求中不重复全套外观，也不以省略导致身份混同 |

## 共通的局部改写示范

任务：首帧是两名剑客刚刚接架，快速分开后再交锋，最后仍对峙；无指定模型。

```text
【身体与武器动作轨迹】白袖剑客右手转腕，将相抵的剑锋引向身侧，同时侧踏卸开压力；深衣剑客收肘抽剑，两刃滑离。白袖剑客趁距离尚近沿空出的下路斜挑，深衣剑客退步压剑挡开，双方随兵器偏转各自恢复支撑，仍握原剑相对。
【运镜】同侧中全景横移跟住这次卸力与反击，双方持剑手、交点和落脚持续可辨。
【命中效果】第一次接架先滑离，第二次格挡只让两剑与上身沿受力方向偏移；短火星在实际相碰时出现，双方最后恢复对峙。
```

此例只展示同一事实如何用运动描述表达，不是完整新场景或已生成成功案例。投喂到不同模型可调整标题/时间表示和绑定方式，不能在转换中把两次不同接触合并或把同一接触重演。

## 诊断与复测

排查顺序：实际输入和控件 → 作者稿与真实提交内容 → 首帧/参考矛盾 → 动作及相机负荷 → 生成偏差。文字已经清楚、输入图仍有错手/错刃时，优先修起点；模型自动扩写或模式切换改变了正文时，先核对实际内容，不继续堆词。

保留基线与候选的素材、设置、正文和输出关联。优先只改最有证据的一层；换模型、素材和正文同时发生的结果只能评估整体方案，不能归因于一个词。动作成立再逐项恢复装饰。现有review-loop.md负责视觉验收，程序检查不替代观看与实听。
