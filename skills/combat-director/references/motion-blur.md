# 运动成像：相对运动、可辨事件与收束

用于战斗运动模糊、快门观感、跟拍拖糊、动画残影或拖影故障。普通静态姿势不必补模糊说明。这里指导画面编排；实际 UE、合成软件或视频平台设置需对应版本和入口证据。

## 先区分现象

| 现象 | 判断与表达 |
| --- | --- |
| 曝光运动模糊 | 哪个部位相对画面移动，沿什么轨迹拖糊；物体和相机运动共同影响结果 |
| 景深虚化 | 哪个距离平面清楚；不以浅景深代替速度说明 |
| 粒子尾迹 | 场景中产生了什么、留在哪里、如何消散，见[粒子行为](particle-vfx.md) |
| 风格化残影 / 动画 smear | 用户选择的短暂姿态叠加或拉伸画法；不增加独立参与攻防的实体 |
| 非预期重影 | 记录实际边缘粘连、旧姿态残留及时间码；仅凭外观不能确定模型架构或处理算法 |

先继承用户要求的正常速度、低模糊、重拖影或动画画法。未指定时不自动添加强烈模糊、固定快门或一套参数菜单。渲染风格与能力授权仍分开。

## 相机与动作一起设计

固定机位中，挥剑不使静止石墙整幅横拖。侧面跟拍减小躯干的画面位移，背景可向相反方向掠过；摆臂、转头和剑尖仍有相对运动。两个对手速度不同，不能承诺两人所有部位同时像静物一样清楚。转动兵器的端点沿弧线扫过，不统一写成水平直线。

先选本镜头需要看懂的事件：谁起动、谁回应、在哪里接触或避开、怎样受力和恢复。可辨是能连续追踪因果，不等于每一帧每个像素都锐利。若用户明确要求逐帧低模糊，采用相应干脆观感；不以一般自然成像建议覆盖用户风格。

连续镜头通常维持一致成像观感，局部模糊随相对运动变化。不要每次交刃都无解释地“关闭一帧模糊”，也不为清晰擅自加慢放、定格或切镜。相机急甩恰好盖住关键接触时，在授权范围内调整镜头安排、构图或非关键叠加效果；两条同等明确要求互斥时，指出对象与时段，让用户选择。

短曝光可减少拖糊，也可能带来顿挫感。真实摄影可用 `曝光秒数 = 快门角度 / (360 × 拍摄帧率)` 理解：24 fps、180°对应1/48秒；这不证明文字生成采用了同样曝光。拍摄帧率、输出FPS、播放速度、渲染采样和后期插帧分别记录。

## 曝光与尾迹分别结束

相对相机停止的物体，常规曝光模糊最多延续到仍包含停止前运动的曝光窗口；它不会像烟一样自行在空气里漂散数秒。相机继续运动时，已停住的物体仍可能产生画面运动。

粒子则可以在停止新增后继续留存。附刃光带与模糊共存时，分别交代剑的实体轨迹、旧光带的位置和退场，不让两层一起加宽到遮住双方持械臂。亮边、火星或残影都不自动成为离体攻击、额外兵器或分身。

## 压缩与两层传递

内部按“具体动作 → 相机相对运动 → 模糊范围/方向 → 可辨事件 → 收束”检查，只把当前镜头必要的信息写进最终提示词。用户只要一句时就给一句可见描述。

> 固定侧面双人机位。甲双手木杖斜劈，乙撤步斜架拨开；杖端快移处留短弧形模糊，招架、滑开和回收过程仍能追踪，背景石墙保持稳定。

工程稿在适用 `beats[].camera.path` 写镜头意图，在相应 `sections[].summary.camera` 保留投喂信息；粒子留存写在 `vfx` 或 `environment`。最终八标签从分段摘要输出，脚本不自动概括逐拍自由文字。总设定不是每段完整审阅事实，先前的镜头文字也不会随状态自动继承；跨段策略要在适用段继续明确。改动后按[契约](contract.md)实际复核，不只刷新签名。

不新增 `motion_blur_strength` 或 `shutter_angle` 等未经支持的 plan 字段。用户给的快门数字可以保留为意图；只有实际工具支持并采用的设置才能记为已执行。

## 平台与参考

图生视频先观察实际输入图是否已有运动线、预烘焙拖影或扬尘；未读素材则标未知。输入暗示与要求相反时指出冲突并提出最小修订，不能声称图已修好。

已观察的输入图通常已提供外观与构图，图生文字重点补运动关系；文生仍需交代必要主体与场景。提示长度、动作数量与时间标签按模型版本、生成模式和实际时长选择，不套用统一字数或逐秒配额。时间标签可表达先后与节奏，精确到帧的接触或路径需有对应控制接口，不能靠增加形容词宣称解决。

按当前模型和入口证据选择正负向措辞。正向可写“同一把剑连续由右手握持，快移处只呈短暂边缘模糊”；不要一边要求自然模糊，一边笼统禁止 `blur`。支持负向入口时再列确实不希望出现的对象，不能猜测API字段或把某一代模型的规则推广到所有平台。

实际观测、创作建议和设置证据分开。运动参考不证明快门被复制，生成请求成功也不证明每项文字要求已执行。

平台可能自动扩写或重写提示词，按[平台交接](platforms.md)记录实际状态。改写不能关闭或正文不可见时，对照结论只覆盖提交文本经过该平台后的整条链路，不声称模型内部输入只差一条模糊描述。没有媒体时只检查文字与设置证据，不预判清晰度收益。

## 故障检查

先看原片、前后连续帧和处理链，再提出修订。没有视频时只能做文字预检。

| 现象 | 先核对 | 修订方向 |
| --- | --- | --- |
| 交刃看不清 | 机位是否急甩、尘烟与光带是否叠盖、动作本身是否完整 | 调整与失败直接相关的机位或叠加效果，保留用户的速度与结尾 |
| 多重手掌 / 剑刃粘连 | 是否用户允许的残影；原图、原片、插帧或补模糊哪个阶段出现 | 保留证据，修正确认的阶段；不靠加模糊遮掩错误握法 |
| 全片清楚但像冻结 | 正常速度观看动作是否发生，是否偷减动态程度 | 恢复要求的动作与节奏，不能以静止通过锐度检查 |
| 跟拍背景方向错误 | 主体、相机和场景锚点的实际相对路径 | 先改路径描述，不用“电影感”掩盖方向矛盾 |
| 收势后仍有长尾 | 尾部属于曝光、粒子还是明确艺术效果 | 分别给停止相对运动、停止发射与存量退场 |

评价分别记录运动关系、攻防可辨、实体/持物、风格与时间；看不清关键过程不能算通过。全片播放与局部抽帧的覆盖范围分开，输出FPS或单帧锐度不能代替这些观察。记录方式见[审片流程](review-loop.md)。
