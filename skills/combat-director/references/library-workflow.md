# 资料检索与招式改编

按[入口](../SKILL.md)确定需要自定或核实的方案，再用[分类导航](../library/index.md)定位候选。项目机制卡提供原创或按用户文字独立改编的设计候选，来源卡保存可追溯资料，均不是成片成功案例；数量由导航维护。通用机制由对应专题维护，卡片只提供本次可用的具体方案。

## 找到最小够用的资料

按未决问题选类别，先看摘要，再读选中卡的改编用法；点名招式查逐招条目。使用前核它与用户锁定条件、题材能力、人数/持手、支撑/地形、距离/时窗及拍法是否相容，局部修改还要守住范围外设定。冲突候选舍弃，不靠新增能力、人物或通路补成相容。

只在前提、动作细节或来源归属仍不明确时展开对应章节/源行；已能写清本场作用与结果就停止，不为凑数量读完全部分类或翻完所有页。章节涉及的前提缺失时补必要邻节；同一来源行已读过，只取新候选的差异。`catalog.json`和`items.json`由脚本检索，不直接整份送入写作上下文。

下列命令从技能目录运行，仅用Python标准库，离线只读：

```bash
python scripts/library_tool.py stats
python scripts/library_tool.py items --query "乌龙摆尾" --school "八卦掌" --min-detail description
python scripts/library_tool.py item arvin-tech-judo-item-655720874f5d --source
python scripts/library_tool.py search scenes --query "甲板"
python scripts/library_tool.py search camera --query "接点 缺口"
python scripts/library_tool.py search styles --query "赛璐璐"
python scripts/library_tool.py search choreography --query "化劲"
python scripts/library_tool.py show arvin-tech-bagua
python scripts/library_tool.py show arvin-camera-spec --source --source-lines 136:143
```

`show`默认只读用途与来源信息；`item --source`展开所选条目的源行。非命名内容可用`show --source --source-lines 起行:止行`选读卡内一段来源范围；只在需要完整上下文时用`show --source`。节选保留归属与原文边界，不能用被裁掉前提的片段证明完整招式。

查询词按空白/逗号分隔，词之间取或；分类、流派、角色、卡ID等过滤取交集。工具没有中文分词或语义搜索，整句零命中可改短词；不自动拿热门卡替代。流派和角色使用精确值，先查`stats.facets_by_kind`。共享卡的关联不代表每个段落都适用该角色。

零命中也可能是资料范围没有该场景或风格：湖面不能为适配船卡而换成甲板，水墨没有独立风格卡时可读[风格专题](style-and-materials.md)。短词仍无相容候选就按用户条件原创，保留来源缺项；不能编出不存在的卡或把无关预设套入本场。

默认每页12项，最多100项；按`total`和`next_offset`续查，页码越界不等于没有资料。卡搜索默认紧凑摘要，`--full`显示完整元数据；`show`默认隐藏原文。未知卡ID会报错，有效卡无命名条目可正常返回零条，此时可读整卡上下文。

## 证据够不够支持具体动作

| 逐招等级 | 原文提供了什么 | 使用边界 |
| --- | --- | --- |
| `name_only` | 名称、别名或参考列提及 | 没有原文路径；允许原创时标明改编，仅限原文时说明缺项 |
| `description` | 用途、位置、效果或组合说明 | 只继承已给用途/效果，未提供路径另作本场编排 |
| `motion_path` | 部分肢体、兵器或受力路径 | 保留已给路径，补本场距离、对手、支撑与回收，不等于完整可执行 |

逐招`--detail`精确匹配；`--min-detail description`包含后两级。整卡的`detailed/outline/original`是另一种分类，不代替逐招核查。同名招式按卡与行内流派分别保留，别名忠实记录原文，不自行合并或纠错。条目只覆盖明确命名表格、参考列与组合，不是全文所有技法的语义索引。

`item`区分原文事实、上下文与`project_adaptation`。共享行说明不能冒充每一招的独立路径；项目补写不升级原文等级。历史谱系、正统性、游戏设定、必胜效果和固定秒数属于作者表述，未经核验不升级为规则。

## 从候选变成此次交锋

将所选资料按类别转成当前事件，来源已有内容与本场补写分开：

| 所选内容 | 成稿方式 |
| --- | --- |
| 动作、连招或机制 | 起态/支撑、身体与兵器来路、对手回应、接触/让空及回收连成一次本场交换；不只列招名 |
| 摄影方案 | 用当前攻击、判断或受力触发景别/路线/焦点变化；例如破盾时守住剑尖、盾缘和承力手，再认回退追 |
| 风格或特效 | 全局选媒介、材料/线面和主形，相关分镜写转面、接点变化与消退；例如金纹从已有接点断开，碎光退后缺口仍在 |
| 场景或多人调度 | 先建立已有通路/地物，再让它影响选路、支撑、遮挡或并发；固定场景只迁移相容方法 |
| 人物打法预设 | 取适用的距离偏好或应对选择，改给本场人物；不顺带继承预设姓名、外貌、能力和整套招表 |

改变用途、接触部位或机制时说明改编。卡的场面标签仅表示候选范围，不证明群战、追逐或模型效果。

对读所选资料具体改变了哪条动作、摄影或视觉句；只有卡名、泛句或禁令时补具体适用内容。数量不证明成稿质量，仅作边界校验的专题无需复述进提示词。

必要时在提示词正文之外记录卡ID、条目ID、源行和改写点。使用JSON计划时，可放入`provenance`；卡ID、条目ID不是`ability_id`，不能当作已激活能力。纯提示词交付保持一个完整复制块，不夹检索日志或内部采用表。

资料卡与索引由仓库生成器维护，不直接改生成内容。源文版本与许可见[第三方说明](third-party-notices.md)；工程数据边界见[契约](contract.md)。
