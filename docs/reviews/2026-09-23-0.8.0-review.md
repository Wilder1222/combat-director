## R01 · P1 · 直接构建绕过生成资料一致性检查

**位置**：[project.py:81](../../scripts/project.py#L81)、[project.py:88](../../scripts/project.py#L88)，对照[validate_release.py:42](../../scripts/validate_release.py#L42)。

`project.py build`只调用结构验证。库校验检查索引类型、卡片路径与存在性，没有核对正文是否仍由固定源文和改编权威生成。只有另一个入口 `validate_release.py` 调用了生成器 `--check`。

**复现**：在临时副本中保留所有正常生成产物，仅将八卦掌卡正文改为两行占位文本。直接构建成功，ZIP实际包含该错误正文；生成一致性检查拒绝同一张卡。README公开列出了直接构建命令，因此调用者不一定经过较严格入口。

**影响**：后续误改生成卡，或修改改编权威却忘记重建时，仍可能得到带固定来源声明的过期/错误发布包。当前经完整流程构建的包没有出现这种差异。

**建议**：统一正式构建入口的生成检查，在写ZIP前完成；解压后的离线运行检查独立保留，不让运行包依赖仓库原件。失败时不得覆盖既有可用ZIP。

## R02 · P2 · 分类筛选字段缺失造成确定性漏检

**位置**：[build_arvin_library.py:241](../../scripts/build_arvin_library.py#L241)，对照[library_tool.py:121](../../skills/combat-director/scripts/library_tool.py#L121)。

连招、镜头、特效记录调用 `add()` 时不传 `schools`、`characters`。这些字段默认空数组，而检索按它们做严格过滤。资料正文和索引条目已经有对应内容，增加正确筛选条件却会删除结果。

| 查询 | 实际结果 |
| --- | --- |
| `search choreography --query 顶心肘` | 命中八极两组短打连段 |
| 上式加 `--school 八极拳` | 0条 |
| `search effects --query 白鸽` | 命中角色特效签名 |
| 上式加 `--character 白鸽` | 0条 |

**影响**：按角色或武学组织战斗方案时，已入库连招/特效可能被误认为缺失，触发无必要的原创补写。现有测试仅覆盖技法与角色卡的筛选，没有覆盖跨分类查询。

**建议**：在编辑权威中显式补充有证据支持的关联，建立跨分类回归；禁止为了增加命中率而给所有卡贴上所有标签。镜头/特效也一律继承双人/演武范围，`camera --scope group`为0；此项需逐卡复核适用场面，不能简单全放开。

## R03 · P2 · 生成卡退役后无法正常重建，失败前已写入其他产物

**位置**：[build_arvin_library.py:269](../../scripts/build_arvin_library.py#L269)、[build_arvin_library.py:286](../../scripts/build_arvin_library.py#L286)。

检查器会拒绝磁盘上多出的 `arvin-*.md`，但写模式只创建/覆盖新结果，没有处理已删除或重命名配方留下的旧卡。它先写全部新文件，再发现旧卡并报错。

**复现**：临时副本中添加一张不再属于配方的旧生成卡，并给现有卡放入旧内容标记。运行重建退出1；旧卡仍在，其他卡已被覆盖为新内容。重复运行不能自行恢复到无旧卡的状态。

**影响**：维护者正常删除或重命名卡片时，规定的“编辑权威→重建→检查”流程不能完成；失败也不意味着工作区未改变。

**建议**：生成前计算新增、修改、退役清单，验证全部输入；仅对有上次生成清单和内容哈希证明的产物执行退役。未知文件或被人工改过的旧卡应在写入前报出差异。先临时生成并验证，再应用变更，失败保留可恢复状态。

## 已确认的能力边界与优化机会

以下两项不是违反当前文档承诺的程序错误，但会限制“招式已吸收”的实际价值。

1. **详情只到卡片级。** `search techniques --query 小内返 --school 柔道 --detail detailed`能命中；原文对应行只有 `小内返 / Ko-uchi-gaeshi`，动作描述为空。当前提示明确解释了detailed不保证每个列名有细节，因此不能将其判为虚报；但调用者仍无法机器筛出“确有动作描述的招式”。应为条目增加独立来源行、详情状态与可选改编字段，保留整卡上下文。
2. **入口容易载入过大的索引。** [SKILL.md:62](../../skills/combat-director/SKILL.md#L62)直接链接整个catalog。当前索引198857字节、146052字符、6540行；无查询的默认第一页也输出12940字符。脚本本身只读索引是正确的，但让模型直接打开整个索引会削弱按需加载。应优先路由到CLI的紧凑摘要，并提供无Python时的分类导航；字符数不等于实测token、延迟或质量损失。
