# Motion blur 系统提示词草案与场景用法

日期：2026-09-23。状态：保留为融入设计稿；0.8.3已按计划形成精简运行规则，文字案例未经视频模型验证。依据[调研](2026-09-23-motion-blur-research.md)，实施状态见[计划](../plans/2026-09-23-motion-blur-integration-plan.md)。

后续实施注：保留本文件为设计草案历史。0.8.3的实际规则见[运行参考](../../skills/combat-director/references/motion-blur.md)，案例与验证见计划；不要求运行时逐字复制本草案。

## 1. 推荐架构

主技能只保留短路由；详细判断放入拟新增的 `references/motion-blur.md`。按需触发包括运动模糊、拖影诊断、快速挥刃、跟拍背景拖糊、慢动作质感与残影要求。普通静态姿势不强制读取。以下草案指导文字编排 Agent，不直接作为每次视频生成的完整 prompt。

拟加入主技能的短入口：

> 涉及运动模糊、快门观感或拖影诊断时，按需读取 motion-blur 参考。先分清主体与相机的相对运动、粒子尾迹和风格化残影，再确定镜头观感与关键攻防的可辨要求。将相关规则同步到逐拍镜头和分段摘要；快门数字未经工具证据只表达意图。

## 2. 可审阅的系统指令主体

```text
你为战斗片段设计运动成像。先继承用户的镜头、播放速度、风格和能力边界，再判断是否需要明确运动模糊；未指定时不额外加入强烈拖糊或固定快门数值。

分别判断主体运动、相机运动、景深虚化、场景中的粒子尾迹和风格化姿态残影。自然运动模糊描述曝光期间的画面相对运动；粒子与残影另写来源、存续和结束。视觉效果不增加实体武器、分身或伤害能力。

每个相关镜头明确：谁在移动、相机怎样移动、哪些部位沿什么画面轨迹模糊、哪些攻防过程需要看懂、如何收势。同一连续镜头通常维持一致成像观感；强弱随相对运动变化。跟拍躯干不等于手脚和兵器同时静止。

保证起动、对手回应、接触或避让、受力与恢复能够被追踪，不承诺所有高速部位每帧锐利。若模糊、烟尘和光带共同遮住关键过程，先在用户允许范围内调整镜头与叠加效果。不得擅自放慢动作、加入定格、改胜负或用遮挡掩盖空间跳变。

用户明确要求短曝光质感、重拖影或动画拉伸时，保留选择并说明适用时段。仅当两条同等明确的要求无法同时满足时，提出聚焦冲突；一般缺项直接采用克制且可修改的创作假设。

图生视频先检查实际输入图中的运动线索；未观察素材就标记未知。自然模糊、源图预烘焙拖影、生成伪影和后期补模糊分别记录，不凭外观断言底层算法。

在 beats.camera.path 中记录导演意图，在相应 sections.summary.camera 中保留投喂所需信息；粒子存续写入 vfx 或 environment。总设定不能替代分段同步。复核动作、镜头、实体数量、余留效果和结尾是否一致。

最终提示词用简洁的可见动作和镜头关系表达，只加入当前镜头必要的模糊描述。按当前模型和入口的证据处理负向文本。未经证实，不添加 API 字段，不声称快门、采样或引擎功能已生效。创作建议、实际设置与观察结果分别报告。
```

这一段是候选规则，不要求逐字装入；实施时应合并已有能力边界、参考核验和双层编排规则，避免主技能、prompt-craft 与新参考重复三份完整正文。

## 3. 内部选择方式

以下是设计选项，不是新增 Schema 枚举，也不向用户强制展示菜单。

| 任务意图 | 优先描述 | 需要留意 |
| --- | --- | --- |
| 未明确模糊风格 | 先写动作和机位；必要时补少量自然运动边缘 | 不自动插满所有镜头 |
| 干脆、短曝光观感 | 快速部位轮廓更分明，动作仍以正常速度完成 | 减少拖糊不等于一定更平滑 |
| 跟拍速度感 | 明确锁定的叙事主体和背景相对方向 | 另一名对手与肢体未必同速 |
| 用户要求长曝光 / 强拖影 | 明确作用时段、轨迹及信息取舍 | 不同时承诺重拖影区域逐帧锐利 |
| 用户要求动画 smear / 残影 | 明确短暂画法、实体归属与回到单一轮廓的时机 | 不把艺术选择当成模型故障 |

## 4. 六个原创场景片段

以下是用于拼入完整战斗提示词的局部示例，不冒充六份完整可发布计划。人物均为测试角色；相机、能力和时间仍需继承实际任务。

### A. 固定机位、普通木杖

**假设：** 无法术，正常速度，固定双人全身机位。

> 甲双手握同一根木杖，从右肩斜落击向乙左肩；乙向外撤步，双手举杖斜架，让甲的杖沿杖身滑向外侧。相机固定，背景石墙保持稳定。甲的杖端只在快速下落段形成短弧形模糊，观众能追踪两根木杖的接触、滑开和回收；停势后木纹重新容易辨认。

检查重点：模糊沿杖端轨迹；不加剑光、粒子或冲击环；不将固定背景横拖来制造速度。

### B. 横向跟拍追逐

**假设：** 甲向画面右侧奔跑，乙落后半步追近；无交刃结果。

> 相机在侧面向右平移，主要跟住甲的躯干，近处栏杆在画面中向左掠过并产生横向模糊。甲右手短刀贴近腰侧，左臂与双腿持续摆动；乙从后方逐渐追近，两人的距离变化保持可见。甲迈过倒木后继续向前，镜头连续跟随。

检查重点：只保证主跟随关系；不宣称所有肢体零模糊；乙不是永远固定在同一个像素位置。

### C. 近距离交刃、短曝光观感

**假设：** 用户偏好干脆质感，正常速度，不切镜。

> 相机从双方侧面小幅横移，采用短曝光般的干脆运动观感。甲右手长剑横切，乙右手剑斜架拨开，乙随即撤肘沿外侧回刺；甲侧身让开并收剑护住胸前。快速挥刃的边缘仅轻微拖糊，持械关系、拨开的方向和后续回刺可以连续追踪。

检查重点：不为清晰偷加慢放或接触停顿；“可追踪”不等于承诺剑尖每帧毫无模糊。

### D. 用户明确允许的局部慢动作

**假设：** 成片 4–6 秒允许慢放，其余正常速度；慢放包含在既定总时长中。

> 4–6 秒只放慢乙侧身避刃、刀尖掠过衣袖外侧这一过程。相机沿原有侧移路径连续运动，袖口翻起，刀尖保留细小运动模糊；双方仍在移动。6 秒后恢复正常速度，甲从掠过后的刀位回收，乙沿刚让出的空处前踏。

检查重点：慢放没有冻结空气或重置姿势；成片秒数没有增长；不把输出帧率当成真实拍摄设置。

### E. 用户指定的二维动画残影

**假设：** 动画画法允许短暂 smear，角色没有分身能力。

> 甲向左闪身的瞬间，外轮廓沿真实闪避路线短暂拉伸，随后落回单一完整姿态。右手仍握同一把刀，乙的直刺从甲让出的原位置穿过。拉伸轮廓只表达动作速度，没有独立站立、再次攻击或被抓住的身体。

检查重点：不因“禁止增殖”删掉用户的动画画法，也不让画法变成新增战斗实体。

### F. Niagara 风格粒子与自然模糊共存

**假设：** 甲获准使用附刃青光，无离体剑气；乙只有实体剑。

> 甲右手剑横切时，剑尖沿横切弧线产生短暂运动模糊，窄青光带从刃后沿实际剑路生长。乙退步让开，甲没有击中物体；旧光带留在掠过的位置逐渐断成暗点。甲收剑止势后停止新增光带，存量光点继续变暗；相机减速保持侧面双人构图，甲的握柄与乙随后前探的剑路仍可辨。

检查重点：曝光模糊与粒子寿命分别结束；挥空不补接触爆闪；旧尾迹不反向贴回收势的剑。

## 5. 双层表达的最小示意

这是字段片段，不是完整 plan JSON，也不声称可独立通过 Schema。

```json
{
  "beats": [
    {
      "camera": {
        "path": "固定侧面双人机位；下劈杖端沿短弧快速掠过，接触与滑开仍能追踪，背景石墙稳定。"
      }
    }
  ],
  "sections": [
    {
      "summary": {
        "camera": "固定侧面双人全身，木杖快移处轻微弧形模糊，保留招架与回收过程。",
        "vfx": "普通木杖与衣料的自然外观。"
      }
    }
  ]
}
```

片段使用现有字段 `beats[].camera.path`、`sections[].summary.camera` 与 `sections[].summary.vfx`；真实计划还需保留完整身份、时间、状态、动作和复核等既有内容。

系统需逐段核对意图是否保留；脚本只负责字段与版本依赖，不承担从任意长篇镜头文字中自动识别物理正确性的承诺。相应复核仍覆盖 `camera_timing`、`identity_action` 与 `continuity`，必要时包括 `ability_cost`。

## 6. 需要避免的写法

| 候选句 | 问题 | 修订方向 |
| --- | --- | --- |
| 全程强运动模糊，所有人和剑每帧绝对锐利 | 同一区域、同一时段的冲突 | 明确重拖影区域或选择较短曝光观感；保留用户明确选择 |
| 打击那一帧关闭模糊，下一帧恢复，绝对写实 | 隐含未说明的逐帧曝光切换/合成 | 用稳定机位与连续可辨过程；确需艺术处理时明确标注 |
| motion_blur=0.2，shutter_angle=90，已启用 | 将未核验的数值冒充工具控制 | 写成视觉意图；实际控制另据当前入口记录 |
| 没有模糊、没有拖尾、没有残影 | 可能误删用户允许的粒子或动画效果 | 明确禁止的是哪种现象；按平台选择正负向表达 |
| 用运动模糊遮住错误手部 | 掩盖因果与身份错误 | 回到原片定位持物/动作问题，再讨论成像修订 |

最终交付采用与当前任务相称的长度；这份设计说明和全部案例不应被自动拼入每个视频提示词。
