# Combat Director 0.8.0 优化计划

制定日期：2026-09-23。依据[实现审阅](../reviews/2026-09-23-0.8.0-review.md)和[复现证据](../reviews/2026-09-23-0.8.0-evidence.json)。当前状态：第一批WP01—WP03已在0.8.1实现并通过33项发布检查、79项测试（另2项跳过）；第二批及独立创作行为评估尚未实施。下文保留原验收设计，具体结果见当前验证报告。

目标：让已吸收资料能够完整检索、准确说明每招的来源与缺项、稳定进入动作编排，并确保所有正式构建都检查生成一致性。先解决已复现的问题，再扩充资料；暂不继续增加卡数。

## 实施顺序

| 批次 | 工作包 | 优先级 | 完成后可交付什么 |
| --- | --- | --- | --- |
| 第一批：修复可靠性 | WP01、WP02、WP03 | P1 / P2 | 构建检查一致、跨分类不漏检、卡片退役可维护；可作为0.8.1范围 |
| 第二批：细化招式与读取 | WP04、WP05 | P2 | 每招可定位、可区分缺项，按需读取更短；涉及索引契约时单独规划版本 |
| 第三批：验证与收口 | WP06 | P2 | 未见任务的语义证据、最终工程回归与交付报告 |

WP01优先；WP02与WP03之间没有设计依赖。WP04以修正后的来源关联为基础，WP05消费WP04的条目；WP06的输入与评价标准可提前准备，最终执行在候选实现冻结后。S/M表示局部/多模块相对工作量，不承诺未经测量的工期。

## WP01 · 统一正式构建检查 · P1 · M

**解决R01。** 涉及 `scripts/project.py`、`scripts/validate_release.py`、生成器检查接口及构建回归测试。

- 让公开的正式构建命令在写ZIP前执行来源哈希、生成卡、索引与覆盖清单的一致性检查；完整发布流程调用同一接口，避免两套规则漂移。
- 区分仓库发行检查与解压包的运行结构检查。后者保持自包含，不要求完整上游快照进入插件。
- 使用临时ZIP完成写入和完整性检查后再替换目标，检查失败不破坏上一次可用包。

**验收**：单独改生成卡正文、改配方后不重建、改catalog、改上游快照四种情况均在正式构建前失败；旧ZIP哈希不变。正常构建重复得到相同字节，解压包可在仓库外运行。

## WP02 · 修正跨分类关联与筛选 · P2 · M

**解决R02。** 涉及生成器中的编排/镜头/特效记录、catalog、CLI及检索测试。

- 在编辑权威中显式定义武学、角色版本和适用场面，区分缺少关联与经过审阅的不适用；不从否定句或任意全文关键词自动授予标签。
- 八极连段关联八极拳；角色特效表关联其实际提供的角色版本。共享卡可以有多个关联，查询结果仍保留角色上下文。
- 复核镜头、效果卡的双人/群战/追逐等适用范围；`stats`或分类概览显示该分类真实可用的筛选值。

**验收**：`顶心肘+八极拳`、`白鸽特效+白鸽`查询不再丢失已有卡；错误角色/武学仍被排除。冰霜与火焰绯雪不能因共享单刀词汇合并。至少覆盖“技法、角色、连招、特效”四类的组合筛选，未知范围不伪装为已验证适用。

## WP03 · 生成器支持退役与失败恢复 · P2 · M

**解决R03。** 涉及生成器、生成文件清单和临时目录故障测试。

- 先验证输入并计算新增/更新/退役差异，再写文件；增加可查看差异的检查模式。
- 用受管理文件清单及上次内容哈希识别旧生成卡。只退役能确认由生成器创建且未被人工修改的文件，不按目录通配符清空。
- 所有目标路径必须留在受管理目录内；先在临时位置生成并验证，再应用变更。应用失败时保留恢复依据，不留下索引与正文互相错配的状态。

**验收**：删除/重命名一张配方后重建通过且旧卡不入包；新增无关文件不被删除；人工修改的旧卡在写入前被报告；输入或写入失败不会损坏先前完整输出；`--check`始终只读。

## WP04 · 将详情状态与来源定位细化到招式条目 · P2 · M

**解决卡片级粒度限制。** 保留现有卡作为武学/角色上下文，新增条目记录，不必机械生成数百个单招Markdown文件。

每条至少记录：稳定ID、招名/别名、所属卡与武学/角色版本、准确源行、来源详情状态。区分“仅名称”“有文字描述”“有明确动作路径”；本项目补写另列，不用补写抬高原文详情等级。

选中条目后，可按需补主攻/破招/收势用途、必要接触、动作路径、对手回应、失败出口和回收。不是所有招式都强行填满同一模板；无法从源文得到的字段保留缺项或显式原创说明。

提供条目查询/读取，例如选卡后再选条目，并返回该条目需要的角色或武学上下文。若变更catalog结构，显式升级索引版本并处理旧ID；Combat Plan1.2保持不变，来源仍可写入现有provenance。

**验收**：“小内返”能检出但标为名称资料，要求有动作说明的筛选不得命中它；“乌龙摆尾”可定位实际动作行；同名“白蛇吐信”的流派版本独立存在；变更生成器后来源与本项目补写仍可追溯，原文空白不被静默补全。

## WP05 · 改善入口路由与读取长度 · P2 · S/M

**解决整索引与整卡加载偏重。** 涉及SKILL入口、库工作流、CLI展示和必要的分类导航。

- 入口优先指向选择方法和紧凑检索，不引导模型先读取6540行catalog。无Python环境提供小型分类导航，仍能直接按需读卡。
- 默认搜索只返回ID、标题、类别、匹配条目、详情状态和必要的适用摘要；完整来源段、长排除清单与原文在选中后读取。
- 默认读取给出改编与选中条目；原文可显式展开，版权与来源信息随资料保留。通用规则集中维护，减少109张卡里反复出现的相同段落。

**验收**：默认第一页显示文本以不超过6000字符为初始目标；一个明确招式任务无需读取整个catalog或所有正文。对比实际读取文件与字符数，同时检查关键信息是否丢失，不把字符节省直接宣传为token或质量提升。原文仍可定位，已有卡ID与零命中行为兼容。

## WP06 · 行为评估与发布收口 · P2 · M

先冻结0.8.0基线和候选版，准备以下请求与语义验收项；不要把预期答案或本轮发现写进执行者的任务提示。

| 请求场景 | 重点验收 |
| --- | --- |
| 八极短打，明确顶心肘 | 找到已有连段，具体动作来自所选条目 |
| 只依据源文写小内返 | 承认动作缺项，原创内容不得冒充原文 |
| 白鸽18秒无能量演武 | 中高位腿法主轴、低位过渡、双方主动回应；无火焰偷渡 |
| 绯雪火焰版单刀交锋 | 不混入冰弓/时停；持械手与刀的数量连续 |
| 凛羽与冰女对练 | 打→抓→打和硬冰封路可区分，按用户能力限制改编 |
| 三人回廊护送 | 全员位置/任务可追踪，双人招式只局部移植 |
| 同名白蛇吐信，指定八卦 | 不移植太极剑或白猿剑的兵器动作 |
| 用户授权自选场景和风格 | 直接作合理选择，具体材质/光线/地形进入动作，无重复确认 |
| 海底或摇晃甲板战斗 | 运动与场地条件相容，不套用无条件地面步法 |

程序用例检查检索与来源；创作输出按动作路径、回应、恢复、版本、能力和结尾进行人工/独立语义评价，不用关键词计数代替质量。独立执行遵循届时的代理授权；未运行则保留“未运行”，不以作者自审充当独立评估。

记录完整请求、实际读取资源、文件哈希、执行条件、原始输出与逐项理由。条件许可时做同环境基线/候选比较；来源族与示例不要全部复用教学样本，保留未见请求。此次只规划文本评估，不涉及上传素材、消耗视频积分或发布。

**最终验收**：第一批三个复现问题关闭并有回归；详情缺项和同名版本无混淆；样本内用户硬约束无退步；六套既有计划与导出仍通过；来源、生成卡、catalog、许可、文档、构建和解压检查一起收口。Windows跳过项与未测宿主/视频能力明确报告，不继续沿用旧成绩。

## 保留项与交付边界

保留现有七张原创机制、九角色版本区分、固定MIT来源、原文与改编分区、六轨与Combat Plan1.2、只读离线检索。暂不加入向量库、外部数据库、自动补齐缺失剑谱、自动能力授权或新平台API。

原计划制定阶段只增加审阅、证据与计划文档，尚未实施上述优化。后续修复状态见下节；代码交付应按实际实施范围更新来源权威、派生产物、测试和报告。
