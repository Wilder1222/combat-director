# 诛仙参考驱动的战斗技能优化方案

状态：已完成本轮技能修改、完整案例、文本检查与本地构建，详见[实施与复核](../../evals/rapid-cut-2026-09-30/jade-full/review.md)。基线：`master@c69dea0`，技能版本保持 `0.10.0`。本轮范围为技能设计与场景文本测试，不包含视频生成或成片效果认证；以下保留原方案以对照实施。

## 1. 优化目标与已有基础

下一轮的目标是：**用稳定的空间与接触规则，生成有招式变化、有法术升级、有人物选择的完整仙侠爆剪场景。** 首要参考为《Jade Dynasty EP34｜凡雪花海对决》，其他国漫案例补充局部技法。

现有入口已支持多机位爆剪、约44镜、快镜0.2—0.4秒、长镜0.6—1.2秒、两处微慢镜，以及情绪驱动的仙侠交锋。本轮不把这些重复列为待新增功能，也不将44镜模式推广为所有战斗的默认规则。

已有证据与下一步缺口：

| 已有工作 | 当前判断 | 下一步重点 |
|---|---|---|
| [两轮场景生成与独立审稿](../../evals/rapid-cut-2026-09-30/analysis.md) | 时长正确不能保证接触、地形与动作接续正确；原始失败已保留 | 将事件事实与时间统计集中维护，避免局部改好、摘要仍错 |
| [30秒44镜修订稿](../../evals/rapid-cut-2026-09-30/revised/epic/answer.md) | 已修复列出的空间矛盾，但属于有限刀芒的地面战 | 保留为低能力回归，另建完整仙侠案例 |
| [情绪仙侠专项](../../skills/combat-director/references/emotional-xianxia.md)与[6.4秒局部样例](../../evals/rapid-cut-2026-09-30/transfer/jade-emotion/answer.md) | 已把情绪变成收招和追击选择，尚未验证完整段落组合 | 在44镜中同时安排实体交锋、能力变化、有效复位与情绪转折 |
| [终局密度样例](../../evals/rapid-cut-2026-09-30/transfer/terminal-density/answer.md) | 已有局部密集接触设计；不能据此认定全长稿终局持续加速 | 分别记录切镜密度、接触间隔与战术升级，复核完整节奏曲线 |
| [诛仙观察记录](../research/2026-09-30-jade-dynasty-ep34-study.md) | 支持兵器与法术轮换、巨树花海纵深、人物选择窗口；属于暂停截图观察 | 只迁移已见的视觉方法，不冒称原片44镜、精确Hit Stop或全段轴线已验证 |
| [跨作品研究](../research/2026-09-30-donghua-crosswork-synthesis.md) | 已积累接触身份、环境反馈、低姿避刃、空中恢复等局部方法 | 按适用条件检索，避免把所有技法堆进同一个场景 |

此方案承接当前提交，不沿用[早期优化计划](2026-09-30-combat-output-review-and-optimization.md)中的旧版本状态。

## 2. P0：先补完整仙侠编排能力

### P0-1　把“动作链正确”推进到“攻防发生变化”

修改 `skills/combat-director/references/choreography.md`、`emotional-xianxia.md` 与 `templates.md`。先写事件，再分镜；每个攻击簇回答五个问题：

1. 这一簇要迫使对方放弃什么位置、路线或防守？
2. 发起者使用哪件实体兵器、哪种已定义能力，作用距离和停止条件是什么？
3. 对方为何采用这次回应，它与上一簇有什么变化？
4. 接触或避让改变了什么状态，下一簇从哪里接上？
5. 人物关系是否改变攻击目标、追击意愿或收手时机？

以“试探实体防线 → 识破并改变线路 → 能力压缩可行路线 → 付出代价破局 → 在可攻击时选择追击或收手”作为本次候选结构，不设为所有战斗的固定五段式。升级至少改变距离、攻击分布、路线、防守方式或代价之一；不能只放大同一光效。

仙术分别写明实体兵器、贴刃光、离体攻击、防御作用区和余光。颜色绑定能力及当前阶段，不能单凭红青认定人物身份。选用空战时才补高度、推进、制动和转向；已有地面案例不随之扩权。

验收：完整新稿的各攻击簇都有不同战术结果；能力没有无来源出现；复杂犹疑由可见收招或放弃追击兑现；不会让来袭者无故暂停等特写。

### P0-2　建立单一事件记录，分镜与摘要从中派生

修改 `rapid-cut-continuity.md`、`assets/sequence-template.md`、`compact-output.md` 与 `quality.md`。采用可读的事件表，不要求创作者先写JSON：

| 记录 | 最少需要的内容 |
|---|---|
| 攻击事件 | 事件ID、攻击者、武器/能力、来路、目标、首触或最近掠过点、分离条件、结果 |
| 空间状态 | B左/A右的轴线、实际间距、相关地标、位移方向；有高差时注明高度 |
| 镜头映射 | 来路→命中点/避让→反馈对应镜号；同一持续接触不能因换机位重复计击 |
| 时间信息 | 镜头入出点、实际接触时刻、Hit Stop、两处微慢的绝对区间 |
| 可读窗口 | 双人及地标实际可辨的起止时间；遮挡或拉焦结束后才计入 |

双脚落点、承重切换和兵器包络只在反向启动、碎板边缘、贴身掠过等高风险位置展开，不要求每镜写四脚坐标。

接入现有结构化工作流时，优先使用 Combat Plan 1.2 的既有动作事实与事件标识；不向严格schema偷偷增加字段。若检查器需要额外时间窗口，用单独的评估记录保存，并绑定源稿哈希，不建立与正文竞争的第二套事实。

验收：正文、逐镜表、六轨与末态无矛盾；手写摘要改为从最终镜表复算；重复覆盖同一首触不会制造额外命中、伤势或撞击音。

### P0-3　完成一份新的30秒／44镜仙侠主案例

保留旧石台稿，新建花海石道与巨树地标的原创测试场景。30秒为本次沿用的测试预算，并非用户新增的硬性总长；44镜、两个镜长区间与两处微慢沿用用户要求。人物、兵器和能力在约束卡中明确为原创选择，不冒充原作设定。

先锁B左向右施压、A右回应，默认不换边；若编排确需换边，必须先展示可追踪路径与空间复位。近身兵器与有限离体能力轮换，升级改变攻防条件；让一次情绪选择改变后续追击，而不是额外插入无因果对视。

可先用以下预算开局，最终以逐镜复算为准：

| 段落 | 镜数候选 | 快镜/长镜候选 | 创作任务 |
|---|---:|---:|---|
| 0—8秒 | 10 | 4/6 | 开场子弹时间后快速进入眼神、刀线和首次接触；建立双方及地标 |
| 8—22秒 | 20 | 8/12 | 连续攻击簇，每簇改变防守、路线或距离；复位包含下一次动作准备 |
| 22—30秒 | 14 | 10/4 | 加密短镜与有效接触，终局微慢释放后继续反馈，以实际选择完成收束 |

这只是可行的镜数/时长分配，不是已完成的逐镜稿或固定配方。每镜仍须落在指定区间；两处微慢与短促Hit Stop都计入镜长，不能另外加时间。若细排导致超载，先简化同一镜内的复合动作，不丢接点、反馈或复位。

验收：44镜完整文本、独立可复制正文、攻击事件表、时间回执和逐镜语义审阅齐备；所有主攻击保留三镜因果。挥空用最近掠过点，不伪造命中停顿；刀剑格挡、身体受击、触地破坏分别给正确反馈。

## 3. P1：节奏、力感与画面信息分工

### P1-1　分别检查切镜、接触和升级

在 `rapid-cut-continuity.md` 增加简短节奏检查，不再只看“有多少快镜”：

- **切镜密度**：分段镜数/时长以及快镜分布；前段从建立关系转入密集交锋，避免开场之外持续低密度。
- **接触节奏**：只统计新的实际接触；列出相邻接触间隔，持续抵压与同一事件换角度不重复算。情绪或复位造成的间隔应有明确用途。
- **升级强度**：列出各簇改变的战术条件。终局通过招式组合、受限路线和代价逐层增加压力，不要求每一击机械缩短间隔。

“短镜更多”“接触更频繁”“终局更强”分别给证据。若终局接触间隔变长，检查是否确有蓄势、复位或人物选择；不能仍用摘要宣称连续加速。

### P1-2　力感按真实受力链分配

修改 `choreography.md`、`particle-vfx.md` 和 `quality.md` 的相关段落：脚下发力→兵器/身体到达→局部接触→躯干传力→滑退/落脚→环境余波。

| 用户要求 | 落地方式 | 不能混淆的边界 |
|---|---|---|
| 脚下发力、石板裂纹 | 先承重和蹬地，再出现授权范围内的局部裂纹 | 不能每次轻踏都裂地；破坏持续影响后续落脚 |
| 滑退、衣料内凹 | 有实际身体接触才做对应压缩；初始退移随冲量 | 兵器格挡不直接制造胸口凹陷，反向启动先制动再发力 |
| 气浪推云 | 明确冲击传播范围，先近处衣摆/尘瓣，再影响范围内云雾 | 远景云不能无传播和能力依据同步被推开 |
| 呼吸断裂 | 文本写明受压点短促断气、恢复窗口换气，并给声音入点 | 尚未实听音轨，不把声音设计记作音频验证 |

### P1-3　机位与特效服务于可读事件

在 `camera-coverage.md`、`particle-vfx.md` 与爆剪专项之间明确职责：眼神镜给决断，刀线镜给来路，近景保接触，低机位表现真实相向推进，高机位交代新间距、地形与下一条路线。

袖、碎石和碎光只掩切点，不能承担空间复位。连续核对双方的方向、速度量级和动作相位；遮挡物本身也有来源与轨迹。高亮集中在接点外围及后续扩散，不能让白光吞掉唯一首触。花瓣、碎石和法术碎光采用不同运动与消散方式。

每3—5秒主动重建站位，状态突变时可以提前；检查真实读位窗口之间的空白，并覆盖开头和结尾。只有光轨、单人远景或一帧露出两人，不算可靠复位。

验收：每个关键镜头能回答“这一镜新交代了什么”；复位既读得到两人又继承战斗状态；音画、特效与接触不互相抢占唯一信息窗口。

## 4. P1：规则组织与可复用检查

### 规则收敛

`SKILL.md` 只保留任务路由、能力边界与核心流程。爆剪硬约束的详细解释归 `rapid-cut-continuity.md`；人物选择与仙术升级归 `emotional-xianxia.md`；`quality.md` 保留检查入口，模板负责填写位置，避免整段规则多处复制。

核心包引用必须留在技能包内，不让发布技能依赖仓库研究目录。研究证据保存在 `docs/research`，运行时仅保留必要方法及条件。LibTV仍维持自包含：先做“核心规则—适配段落”的对应检查，再通过现有构建脚本生成交付物，不改成指向外部参考文件的薄壳。

### 检查器分层

先在评估目录整合已有脚本，稳定后再决定是否提取到技能脚本；保持标准库实现。不为本次计划改动现有Combat Plan契约。

| 层级 | 可自动检查 | 仍需语义/媒体审阅 |
|---|---|---|
| 时间 | 镜号、镜数、连续性、镜长区间、总时长；微慢区间是否越界 | 变速是否真的可读、动作能否在镜内完成 |
| 事件映射 | 声明的事件ID、三镜顺序、重复首触、接触间隔 | 漏写事件、实际可达性、真假接触及完整因果 |
| 读位窗口 | 窗口在镜内、前后空白、遮挡结束与读位声明的时间关系 | 画面是否能辨认双方、轴线、间距与地标 |
| 特定几何 | 显式脚掌包络、碎边净空、已定义刃段扫掠 | 自然语言完整理解、人体动力学和未声明三维碰撞 |

保留未知与不支持状态，不把缺失记录当通过。回执绑定源稿哈希；主任务编辑复核和独立生成/审稿分开标记。后续只有确实安排了独立测试才使用“独立”结论。

负例至少覆盖：时间摘要漂移；复位标题存在但实际遮挡超时；同一首触换角度被算两击；脚点安全但靴底压空；刀尖避开而刃身扫中；切点前后无制动反向。几何反例继续使用对应的显式输入，不能声称靠通用时间检查器发现这些问题。

## 5. 实施顺序与验收

| 顺序 | 交付物 | 完成条件 |
|---|---|---|
| 1 | 事件表和仙侠攻击簇编排规则，更新既有参考与模板 | 能表达武器、法术、人物选择和状态继承；没有重复事实源 |
| 2 | 新的30秒44镜仙侠案例及完整审阅 | 时序通过；来路、接点、反馈、轴线、复位无已知硬矛盾；未解决细节明确列出 |
| 3 | 整合的文本检查入口与针对性负例 | 可复算时间、事件间隔、读位窗口；缺失数据明确失败或未知；回执可追溯 |
| 4 | 精简后的技能路由与LibTV对应更新 | 核心/适配的关键约束一致；LibTV自包含；生成产物由构建产生 |
| 5 | 回归记录与发布检查 | 新例通过不以旧例退化为代价；通过后再确定版本及发布范围 |

回归集按风险选择，不把每个局部样例都重写一遍：

1. **完整仙侠新例**：44镜、两处微慢、实体与能力切换、可见情绪选择、终局升级。
2. **旧地面石台例**：保留低能力上限、地形继承、承重和遮挡接续。
3. **窄廊换边例**：先展示换边路径再建立新屏幕关系，不能切镜瞬移。
4. **预算过载例**：拒绝不可行的原时长，明确候选改动，统计与逐镜表一致。
5. **局部困难例**：从持续接触、碎板净空、整刃避让、读位延迟中选受改动影响的用例与负例。
6. **模式隔离例**：普通无魔战斗与明确一镜到底请求不继承44镜爆剪或仙术配置。

工程验收包括发布资源/链接检查、受影响的契约和提示词测试、核心与LibTV构建，以及生成文件一致性。工程通过、文本语义通过和成片通过分别记录；当前轮次只要求前两类。

优先完成第1—2步，再依据完整案例暴露的问题收紧规则。之后如继续研究参考片，优先补374—377秒近身路径、377—394秒剑形光因果及433—604秒升级与人物选择的连续观察；不以增加零散截图数量代替完整事件证据。
