# Combat Director 可见动作与镜头表达优化方案

日期：2026-10-01。状态：资料整理、方案及技能实施已完成；媒体复测、安装更新和发布尚未执行。实施范围与验证见[本轮记录](../implementation/visual-action-review-2026-10-01.md)；下文保留制定方案时的基线和分批安排。

本轮目标：让战斗提示词产生可见的攻守变化、身体位移和有目的的镜头变化，同时保留身份、兵器与因果连续性。以本线程两份失败样片和《时序局》分镜稿为新证据，不把某一种剪辑、参考输入或平台设为唯一解法。

## 3. 设计原则调整

### 3.1 先选择战斗要呈现的变化

每个主要事件先回答：来袭迫使对方放弃什么？回应改变了哪项身体、空间、兵器、防线或环境状态？下一次威胁从这个结果怎样发生？

在导演稿内用简短的“起态 → 攻击/回应 → 可见终态 → 下一威胁”检查。原有六轨、事件表和状态记录继续使用，不新增一套竞争的合同。关节细节只在解释关键结果或适合当前景别时进入投喂稿。

持续接架、压制和滑退仍可使用，但须有用途和结束条件，例如逼向危险边缘、压断支撑或争夺兵器。仅为证明受力而把同一姿态维持数秒，应重新安排。这里不设置所有战斗通用的秒数上限，不否定有意角力、演武、蓄势或情绪停顿。

### 3.2 连续的事件可以用不同方式呈现

将动作事实与镜头显示方式分开：事实层维持身份、兵器数量、实际路线、攻击机制和结果；显示层允许按项目风格选择实时间连续观看、动作匹配剪辑、短促冲击强调或高速省略。

- 关键转折优先让人读清来势、作用/避让与结果，可合在一镜，也可多镜分工。
- 次要连续交换允许用运动线、拖影、声画和短镜概括，但不把省略段中的每一次接触计成已核验事件。
- 遮挡可用于剪辑和风格表达；不能凭遮挡声称一个未展示的决定性反制已经成立。
- 明确的一镜到底、固定镜数、微慢次数和结尾要求继续优先；没有这些要求时，不能从旧案例自动继承。
- 风格化表现不等于新增世界观能力。人物变成一条光迹可以是速度表现，不能顺势获得原设定没有的瞬移或穿墙能力。

### 3.3 用变化组织镜头，避免两种固定配方

避免默认全程平稳双人中全景，也避免默认每击恰好三镜。按当前事件选临近来势、擦身避让、接触、结果尺度和空间重建；可以一个镜头承担多项任务。

“动作因果完整”保留为通用要求；“B固定左侧、每击三镜、两处微慢、每3—5秒复位、约44镜”应标为特定处方。用户明确选用该处方时仍严格执行，其历史案例和验证也继续有效。泛泛要求多机位、高燃或爆剪，不自动等同于接受所有数值与左右设定。

### 3.4 参考素材按实际控制范围选择

继续支持纯文本、人物图、双人动作图与动作视频等路径。人物图负责身份服装；动态构图负责姿态/空间；视频可参考节奏与运动。每项都需要真实绑定证据。

不得由本次失败建立“没有动态起始图就不能生成”的前置门槛。需要做图或视频对照时，先检查当前模型入口能力，并核对兵器、角色数、能力等级和空间是否匹配。用户参考片中的长柄兵器打法不能不加转译地移植成双长剑。

## 5. 下一轮短片实验设计

### 5.1 共同目标

保持原双女身份、服装、右手双剑、宫阙云间御空和8秒长度。先写清三个主要结果：接近攻击迫使对手让线；攻击余势造成相对位置变化并给出回击窗口；回击使另一方改变路线，结束时双方处在可辨的新关系中。

这是一份待细排的事件目标，不是已经可提交的最终提示词。不引入毁楼、巨型法相或不同兵器，不把整段主要时间留给静态压剑，也不预先要求所有场景都采用这个结构。

### 5.2 先做零生成成本的准备

1. 重查模型、模式、时长、引用语法和当前schema；保存日期及完整能力证据。确认720P请求与480P产物差异是否能由可见任务记录解释，不能靠猜测修参数。
2. 给同一事件草稿写连续镜版本A和多镜覆盖版本B。两版动作、素材、时长、效果和速度意图保持一致，只改变镜头覆盖；镜数按信息需要选择，不套44镜。
3. 人工走通攻击路径、避让时机、剑长与实际距离、转身/推进来源；列清每个结果应在何处可见。仅对高风险接点细化，不把全部几何检查塞入提示词。
4. 确认复制正文独立完整、处于当前入口限制内；保存正文哈希、素材顺序与设置。提示扩写保留同一已确认状态；若无法关闭或回读，明确测试的是整条平台链路。

### 5.3 受控试生成顺序

付费执行仅在用户授权的任务范围和预算内开展。本方案本身不启动任务，不设置无限自动重试。

| 阶段 | 对照方法 | 能回答什么 | 不能回答什么 |
|---|---|---|---|
| A/B 侦察 | 同一新动作，连续镜A与多镜B；固定身份图、模型入口、时长、请求规格、扩写状态、声效意图等 | 哪种覆盖在这组输入下更接近目标，暴露主要失败位置 | 两个样片不能证明一般成功率；新动作与旧8秒差异不能仅归因于镜头 |
| 偶然性复查 | 若某版明显更好，按授权预算重复该版；支持种子时记录，不支持时注明 | 改善是否至少能够再次出现 | 不以两次重复宣称稳定生产或统计显著 |
| 定向输入对照 | 两版均失败且证据指向姿态/空间输入时，再保留同一文本和设置，只加入适用动态参考 | 额外视觉输入在该案例是否有帮助 | 不同时换模型、动作、服装和参考，也不据此宣称动态参考必需 |
| 扩写或模型对照 | 仅在前述证据不足且用户决定继续时，单独改变扩写状态或模型 | 记录新的平台条件下的结果 | 不混作本轮纯镜头对照，不拿隐藏改写推定直接模型行为 |

首轮先限定为一对A/B候选，最终任务数和费用在执行时按实际授权确定。任一版本的实际时长/分辨率/引用与另一版不一致时，先标记不可直接对照；不得为了补齐而自动重复扣费。

### 5.4 验收和停止条件

审片顺序：正常速度完整观看 → 标记不成立事件 → 局部原始连续帧检查 → 音轨实听 → 与实际提交记录对读。没有播放/实听能力时明确未完成相应验收，不以密集抽帧替代。

每个主要事件记录“完成/未完成/未知”，附时间区间与证据；三项预定关键结果均须可辨，不能用完成了两项掩盖缺失的转折。另做以下观察：

- 攻击是否迫使对方变化，双方是否只是保持固定姿势一起移动？
- 是否看出攻击加速、避让、错身或追击的差异，而非仅有镜头横移和衣摆运动？
- 接架之后是否明确分离并进入下一状态？持续接触有无实际用途？记录无目的停留时长，但不制定所有风格通用的秒数阈值。
- 关键攻击的来势与结果能否联系起来？切镜有没有掩盖武器复制、无因换边或重复命中？
- 用户对力量、速度、压迫和整体观感是否接受？工程合规不能覆盖用户的观感否定。

首轮若两版都未达到主要事件目标，停止同文本抽卡；归档失败，选择一项有证据支持的新变量。若规格不符或关键路径看不清，先处理交付/证据问题，不宣布风格优化无效。未复现改善前只称“候选改进”，不称“已修复”。

## 6. 技能文本回归与实施验证

媒体试验与技能文件修改分别验收。后续规则修改至少对读以下任务，不预设自动化关键词断言能够判定观感：

| 用例 | 保留的条件 | 要阻止的误用 |
|---|---|---|
| 普通双剑实战 | 无魔、有限破坏、合理可达 | 为追求冲击自动化为流光、踩裂整栋建筑 |
| 明确一镜到底 | 连续机位和空间路径 | 用爆闪偷偷剪辑，或机械要求每击三镜 |
| 一般多机位仙侠 | 自选合理覆盖、允许跨镜展示同一事件 | 自动套B左A右、44镜、两处慢动作 |
| 明确44镜处方 | 原镜数、方向与节奏要求 | 借“放松规则”删掉用户的硬约束 |
| 角力或有意停顿 | 有目标的持续接触、蓄势与表演 | 将所有接触超过固定秒数判成失败 |
| 高速风格化战斗 | 强运动表现、选择性省略和关键事件 | 把所有模糊视为瑕疵，或把看不见的数百次攻击记为已验证 |
| 引用缺失与规格漂移 | 图片绑定、实际正文与文件探测 | 从作品名推断已绑定视频，从设置推断产物符合规格 |

实施后的检查按改动范围运行：Markdown链接及范围自检、导出兼容和既有验证。方案阶段仅查文档链接、来源哈希与diff；后续技能实施批另运行项目完整验证与本地构建，包括 `python scripts/validate_release.py` 和 `python scripts/build_libtv.py`，结果独立留档，不将构建称为发布。

## 7. 交付次序

1. **本次已完成**：原文去重索引、可迁移方法、冲突清单、失败证据归档和此优化方案。
2. **实施批已完成**：P0规则范围与可见结果修改，配一组共享事件的A/B文字稿，完成作者语义走查与本地验证；新案例均标为未生成，未进行独立模型行为试验。
