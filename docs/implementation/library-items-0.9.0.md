# 0.9.0：逐招来源与紧凑读取

日期：2026-09-24。落实整体优化计划WP04与WP05；WP06独立文字创作比较另行执行。当前41项工程发布检查通过，未生成视频、升级宿主或提交推送。

## 数据与来源

保留版本2卡索引及全部116个旧ID，增加版本1条目索引。固定Arvin来源中的命名表格、参考列和连招组合生成1,466个条目，分布于59张技法、角色和编排卡：590项只有名称，166项有文字描述，710项含部分明确动作路径。数量是索引记录数，不是经鉴定的独立武术招式数；不同角色版本、流派与组合分别保留。

每项包含稳定ID、所属卡、源文名称/别名、行内流派、角色上下文、准确源行、原文行、列名和值、详情判定依据。身份由所属卡、规范化名称与流派计算，不含行号或详情等级。共享卡的所有流派不自动继承到每个条目。同一罗马音Hane-goshi在原文对应“跳腰”和“针腰”，保留两个条目，不擅自纠正来源。

详情判定权威在[scripts/arvin_items.py](../../scripts/arvin_items.py)。命名列与来源列角色显式列出，少数用途栏中的动作路径经逐行选择；只写节奏、效果或名称组合的动作栏降为description。名称概览和共享参考清单一律不升级为独立动作路径。共享行的多名称不假定同义，也不将该行文字当成每项都已独立展开。

| 小内返 | 1808，name_only | 中文名、Ko-uchi-gaeshi可查；动作缺项保留，不命中最低description筛选 |

| 体落 | 1800的“打戏价值”栏含转体、手拉关系 | 不仅按列标题识别动作路径 |
| 崩袈裟固 | 1881只写“袈裟固变体”，description | “动作描述”标题本身不会使它升级 |

等级只评价原文给出了什么，不验证历史正统、物理可行性、能力权限、完整性或生成效果。项目补写始终位于project_adaptation，只有整卡改编范围；回应、失败与回收仍按实际场景组织。用户要求只依据原文时不得用补写填平空白。

生成覆盖记录见[覆盖清单](arvin-library-coverage.json)，包含有命名条目的表格、列角色、源行、等级例外及未建条目的上下文表。没有从自由叙述自动推断全部招名，条目零命中可返回整卡检索。

## 检索与兼容

新命令 `items` 返回紧凑候选，`item ID`只显示选中条目、必要整卡上下文和分开的项目建议；`--source`附加选中原文行。索引搜索不读取所有卡正文，未知ID报错，正常零命中不填充热门卡。

原 `search` 的排序、筛选、分页不变，CLI默认精简展示，`--full`取回完整元数据；Python search API仍返回完整结果。CLI `show`默认只显示改编及归属，`--source`恢复整卡摘录；Python read_card API默认仍返回全文。原版catalog内容逐字段与冻结0.8.3一致。

新增[总导航](../../skills/combat-director/library/index.md)及九个分类页；最大分类导航2,074字符，可在无Python环境下先选分类再分段读卡。109张生成卡的共有改编规则转为指向[库工作流](../../skills/combat-director/references/library-workflow.md)的链接，固定提交、原文段和MIT归属保留。新索引和导航进入原有暂存、退役、回滚及漂移检查。

## 实际读取对照

以冻结的0.8.3为读取基线（不是WP06指定的0.8.0创作基线），同环境执行同一组CLI。计数为解码后、LF换行的Unicode字符；原始输出、SHA256、数据文件读取路径在[测量记录](library-retrieval-0.9.0.json)。

| 命令/流程 | 0.8.3 | 0.9.0 |
| --- | ---: | ---: |
| search all 默认第一页 | 13,334 | 3,377 |
| 查询八卦掌乌龙摆尾所在卡 | 1,519 | 624 |
| show arvin-tech-bagua | 3,492 | 861 |
| show arvin-character-baige | 3,512 | 767 |
| stats | 4,323 | 4,323 |
| 旧版查询+整卡 / 新版逐招查询+选中条目 | 5,011 | 3,281 |

新逐招默认第一页4,519字符，两个默认入口均在初始6,000字符目标内。显式展开原文或选择更大分页会增加输出，不设置截断以掩盖信息。

代价也要记录：新增items索引为1,835,908个字符，脚本内部读取它及151,827字符的catalog；旧流程读catalog和选中正文。新流程减少给调用者展示的内容，增加了本地索引数据量。没有测量token、延迟、费用或创作质量，不能据此宣称这些指标改善。
