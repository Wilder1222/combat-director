## 失败、条件变化与实际加载证据

共9次调用记录全部保留，最终3次用于上述判断，前6次不能计为候选通过：

1. 全局CLI0.147.0无法调用当前配置的模型，任务在模型执行前失败。随后使用应用已有的CLI0.154.0-alpha.6.2，没有全局安装或修改模型选择。
2. 初次只读沙箱执行遇到Windows进程创建错误。单次调用改用只读unelevated沙箱后有命令返回，但候选目录仍不可访问。
3. Python3.13的`mkdtemp`在Windows使用0700权限，临时目录只给所有者、管理员和SYSTEM权限，排除了沙箱身份。后续新建目录继承既有`D:/Temp`权限，没有修改旧目录或用户配置的ACL。
4. 正常目录选择失败时，H02回退到日常已装0.8.1。仅请求关闭同名插件的配置覆盖没有解决该现象；最终测试用CLI已列出的`plugins`功能开关，在单次调用关闭插件发现，隔离同名旧版。其他宿主技能仍可用。
5. 中文Shell输出多次出现编码损坏，0退出不能视为可读正文。最终模型自行用Python读取UTF-8并以ASCII转义JSON返回；父任务解码后与冻结文件正文核对相等。H01匹配motion正文，H02匹配SKILL和motion正文。失败读取也保留在事件记录。

这验证的是上述明确条件下的独立项目技能。它不证明默认多插件环境总会选择0.9.1，也不证明日常桌面插件已升级。普通安装仍是0.8.1；若后续部署新版，应单独检查同名来源，而不是仅看回答是否出现“运动模糊”。
