# 仙侠融合：事实与状态契约研究

日期：2026-10-09。范围：P1/P3 的可选工程状态，软件发布版本另由项目统一。此记录说明方法来源和已实现关系，不证明生成媒体改善。

## 当前代码缺口

原 1.2 的 combat_action 将一个 cast 身份视为一具身体，held_items 既作为手部占用又承担全部持物事实；重复物件被全局拒绝，transfers 只能从当前持有人出发，落地后的物件只剩事件内 destination，后续无法拾取。临时 contact 是字符串，无法核对两条接点中仅一条释放；能力只有全局 active 集合，无法区分同貌身体的独立发动。事件按开始顺序立即转移持物，重叠事件的开始/结束状态不能准确回放。审片只携带文本终态，缺少实际观察的新状态通道。这些缺口由现行实现和新增场景负例核对，不以旧测试通过视为覆盖。

## 一手资料与实际采用

- [JSON Schema 2020-12 Core](https://json-schema.org/draft/2020-12/json-schema-core)区分方言、词汇、断言和组合子。项目继续使用该方言，明确支持 oneOf/anyOf/allOf 并递归审计；不把 $schema 的声明当成通用验证器合规证明。结构版本 1.3 与软件版本分开，新动作格式显式判定，旧读路径保留。
- [JSON Schema 2020-12 Validation](https://json-schema.org/draft/2020-12/json-schema-validation)把默认值归于元数据，并定义 required、类型、唯一项等结构约束。项目不据 default 补造未知身体/物件事实；状态字段与域内引用分别由 Schema 和语义检查负责。oneOf 用于旧/新互斥状态，anyOf 用于重叠的部分状态补丁。
- [W3C SCXML](https://www.w3.org/TR/scxml/#parallel)允许多个状态同时有效，并以确定的顺序处理转换。这里采用同时在场/同时维持与确定时间端点回放，结束先于同刻新开始；不把并发误改成串行打击。资源冲突需明确共享机制；同刻两次写同实体被拒绝。没有引入 SCXML 解释器或将身体动作约束为整套层级状态机。
- [Microsoft Event Sourcing](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)讨论由事件重建状态、语义意图、版本演进和冲突测试。这里采用同一初态 + 带原因的事件操作重放、只读投影和给定初态/事件/终态测试。创作计划仍可编辑，改动使复核失效；没有增加永久事件数据库、消息系统、CQRS 服务或 append-only 发布流程。

## 设计取舍

1. 采用 Combat Plan 1.3 中可选的 combat-action-state/2，保留 1.1/1.2 及 1.3 中未启用新格式的旧动作语义。显式迁移只升结构版本并清空复核，保留旧事实；作者需要扩展时再重建已知状态，未观察内容不被批量填入。
2. body_profiles 只绑定身份/身体和能力来源，动态状态集中在 action_initial_state；items.holders 为持握唯一权威，身体不再存 held_items。实体位置、实际遥控者和自主控制依据分别记录。
3. 接点为成对关系；多个接点局部释放仍保留其他连接。效果把发射后在途对象与供能/遥控实例分开，依赖能力以 ID@BODY 标明。阵法附着、朝向、范围和节点分开，避免局部断阵自动清空全阵。
4. state_ops 是事件内的权威变化，不另加手写状态摘要。event.end 才生效；同一事件内操作原子更新，以支持先断连接、再结束身体或先放物、再退场。state_delta 只承载身体姿态/损伤/持久代价与环境变化，拒绝重复写持物或生命周期。
5. 新事实进入原复核摘要，旧 1.1/1.2 已审哈希不被无故改变；新 1.3 包含结构版本与身体档案。前拍事件与状态操作进入后续继承摘要。语义正文仍独立复核，不能通过更新哈希宣称动作完整。
6. combat-take-review/2 的结构观察初始为 null，只有归属明确的观察才填写。combat-continuation/2 携带观察状态，不能把计划终态填作已知；结构观察未知时保留普通文字未知接续，拒绝伪造完整结构起态。

## 独立反例后的修正

第二轮先读取 state-audit-round1 的原始输入，并在未改输入的情况下重现八处期望差异。遥控只核对声明能力、事件只验开始时刻、接点可更换身体、跨段来源被迫改写及 completed 可复活，均为实际实现缺陷。另对照 semantic-audit-round1/F07，确认自然语言的兼持例外与“一手一物”工程规则矛盾。原输入按字节复制到 tests/fixtures/state-audit，存入 SHA256；回归不依赖私有输出目录，也不修改独立审计结论。

再次对读 [SCXML 的转换选择与执行](https://www.w3.org/TR/scxml/#SelectingTransitions)：条件属于转换是否成立的判断，不能把初态成立视为后续一直成立。项目据此在每次事实转换后重查未结束事件；允许通过显式 interrupts 取消原行动，再从新接点继续。此为项目对原则的实现选择，未引入完整 SCXML 运行时。沿用 [事件状态投影与版本原则](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)：原 pending 来源与接点身份稳定，新进度是对既有事件的更新，不换来源冒充另一次发生。

修正内容：remote 要求控制身体的当前 active 发动；中断该发动时物件仍存在，但作者须同步解除遥控并指定去处。autonomous 和无依赖的自持余箭继续独立运作。接点固定身体/物件而允许同对象滑动；pending 可多段 ongoing，但来源/参与者不变，完成必须显式 continues，终态不能复活。

hand_exceptions 位于同一动作状态内，限定身体、手、物件集合、握持/能力来源、是否允许分指和活动阶段。机械兼持需既定握持依据；能力例外需归属和当前发动。它只豁免匹配范围中的占用，不能绕过 no_hand、其他接点或未声明物件。24 个新测试方法包含原八个独立输入，以及显式中断后续接架、退场取消未来回调、接点滑动/新建、两段未完接续、能力兼持及分指的正反例。全部为合成结构回归，不声明媒体或物理成立；原独立代理还须复查最终实现。

## 链式中断与声明合法性的修正

round2 原审计重放的 30 个旧输入全部符合期望，同时找到三个新缺口。STOP_A 的未来中断被 STOP_B 取消，回放已正确让 LONG 完成，action_text 却从全部计划声明生成另一份中断表；这是事实投影分叉。机械兼持许可的 allows_casting=false 只在已有 effect 占手时检查，新发动仍能越过许可。取消回调还跳过了域 Schema 与能力声明检查。四个触发输入按原字节存入 tests/fixtures/state-audit-round2，原审计输入及报告不被改写。

重新对读 [JSON Schema 的结构断言](https://json-schema.org/draft/2020-12/json-schema-core)与 [SCXML 的生效转换](https://www.w3.org/TR/scxml/#SelectingTransitions)：合法的数据声明与当前能否执行是不同检查；候选转换不等于生效转换。项目据此先检查全部计划回调的域结构和声明引用，再只对实际生效回调核对持有、发动和生命周期。取消的合法 end 能力可以尚未 active；未声明能力和未知 value 字段仍失败。正文直接使用 validate_action 的有效回放轨迹，链式取消不再另推导中断关系。

新增正反例检查链式中断后的真实拾取、取消回调的未知字段/身体/能力、取消回调不强加未发生的 active/接点阶段，以及新施术与途中接物时的手部许可。当前契约回归 29 个方法通过；另用 round2 原 21 个计划逐一核对，全部符合原期望，链式中断正文与权威终态一致。旧工程 62 个方法仍有 61 个通过、1 个系统 symlink 跳过；最终原审计 round3 复查单独记录。

## 器物操作与独立施术的分界

round3 保留的 51 个旧正反输入全部通过，10 个相邻探查中电击棍自身拇指开关被误判为独立施术。原先把 ability_use 与 hands_used 直接等同于施术动作，忽略了同一手对自身持物的操作职责。修正采用 ability.trigger_spec（independent/held-item + source_item_id），结构优先，明确源物件、能力归属和执行身体；不按自由文本关键词猜测，也不按非超自然标记全部豁免手部占用。

原输入没有新字段而要求兼容读取，故只保留狭窄兼容解释：非超自然能力、当前选中 held 源物件、声明手每只只持该同一物件。多物兼持不进入该默认范围，需明确触发结构；显式 independent 覆盖兼容解释，仍受 allows_casting 限制。持握器物引法可以是超自然能力；只在精确源物件及真实持握手匹配时成立。能力自身的结构声明属于事实，生效分类取自同一回放而非正文关键词。

这是对 [JSON Schema 元数据与断言边界](https://json-schema.org/draft/2020-12/json-schema-validation) 的应用选择：触发自由文本保留创作表达职责，新结构提供可核对的种类和引用；默认兼容规则不制造另一份手部或物件状态。新五项方法覆盖原字节输入、显式种类优先、源物件/持手/身体/能力不匹配、非超自然独立动作及多物兼持分界、旧结构隔离与摘要失效。当前共 34 个契约方法通过，round3 的十个相邻计划均符合原期望；实际空间、机关动作与媒体质量仍未验证，等待原审计 round4。


round4 的原 61 个输入及新增 21 个触发关系全部通过，正文仍发现一条无依据的固定句：空手独立施术却宣称持物手使用明确分指许可。本次只删除该固定资源/许可断言，保留同一回放的触发类型；没有新增状态或改变关系校验。原空手输入按字节复制并增加正文断言，35 个契约方法通过；等待原代理有界 round5 复查。
